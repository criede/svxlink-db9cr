SvxLink DB9CR APT-arkiv

⚠ Denne side er oversat automatisk med kunstig intelligens og kan indeholde fejl. Den engelske version er gældende. (English)

Pakker af svxlink-db9cr til Raspberry Pi OS og Debian, i to komponenter — vælg én:

  • main: daglige udviklingsbuilds fra den nyeste kildekode i denne fork, ikke stabile udgivelser.
  • release: de officielle upstream-udgivelser af SvxLink (26.05 og nyere), bygget fra den uændrede upstream-udgivelseskildekode med de samme byggeindstillinger og funktioner som de daglige pakker. Alle udgivelser bevares; apt upgrade skifter til hver ny upstream-udgivelse.

Se kildekodearkivet for detaljer.

Upstream og lokale ændringer

Dette er en dagligt synkroniseret fork af sm0svx/svxlink, det oprindelige SvxLink-projekt, med lokal pakning og ekstra funktioner lagt ovenpå (RTL-SDR, SipLogic, den separate qtel-pakke, dette APT-arkiv og mere — se CHANGELOG.MD for den fulde liste). For at se præcis, hvad der afviger fra upstream på et hvilket som helst tidspunkt, uden at være afhængig af et øjebliksbillede her, der bliver forældet, kan du sammenligne live på GitHub: upstream master … denne forks master.

Hurtigstart

Kør på målsystemet (finder automatisk det rigtige kodenavn/den rigtige arkitektur):

# Importér den offentlige signeringsnøgle
# (kun nøglen med dette fingeraftryk accepteres: E9CF E946 7D00 3148 AB93  EBAC 4ED4 4F53 51D8 1844)
tmp=$(mktemp -d)
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | gpg --quiet --homedir "$tmp" --import
gpg --homedir "$tmp" --export E9CFE9467D003148AB93EBAC4ED44F5351D81844 | \
  sudo tee /usr/share/keyrings/svxlink-db9cr.gpg >/dev/null
rm -rf "$tmp"

# Tilføj arkivkilden. Vælg komponenten:
#   main     daglige udviklingsbuilds
#   release  officielle upstream-udgivelser (26.05 og nyere)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Påkrævet før første start: konfigurér din station, radio og lyd.
# Den medfølgende fil er kun en skabelon og skal tilpasses din opsætning.
sudo editor /etc/svxlink/svxlink.conf

# Aktivér SvxLink ved opstart, og start den nu.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Kontrollér tjenestens status, og følg dens log.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Valgfri grafisk EchoLink-klient (kræver et skrivebordsmiljø):
# sudo apt install qtel

Påkrævet: Start ikke tjenesten, før du har redigeret /etc/svxlink/svxlink.conf. Konfigurér som minimum stationens identitet, logik, modtager/sender og lyd-/PTT-indstillinger til din hardware. Tjenesten læser denne sti via /etc/default/svxlink.

Hvis apt update melder 404 for denne kilde, bygges dit systems kodenavn endnu ikke (se tabellen nedenfor) — ret i stedet kodenavnet i /etc/apt/sources.list.d/svxlink-db9cr.list til et af de understøttede. Derefter henter en almindelig sudo apt upgrade automatisk nye daglige builds (main) eller nye upstream-udgivelser (release).

Aktivér ikke begge komponenter på én gang, medmindre du ønsker de daglige builds: De har altid det højeste versionsnummer, så apt ville installere dem i stedet for udgivelserne. For at skifte en eksisterende installation fra main til release skal du ændre komponenten i /etc/apt/sources.list.d/svxlink-db9cr.list, køre sudo apt update og derefter installere udgivelsesversionen eksplicit (det er en nedgradering), f.eks. sudo apt install svxlink=26.05.2-2~deb13. Bemærk, at i release-pakker (uændret upstream-kildekode) er TCL-scriptene under /usr/share/svxlink ikke beskyttet som konfigurationsfiler; læg lokale ændringer i events.d/local/.

Anvendelse af konfigurationsændringer

Efter at have redigeret /etc/svxlink/svxlink.conf (eller en modulfil /etc/svxlink/svxlink.d/*.conf) på en kørende station kan du genindlæse den uden at afbryde en aktiv session:

sudo systemctl reload svxlink.service

Dette sender SIGHUP, hvorved SvxLink genindlæser sin konfiguration. Brug i stedet sudo systemctl restart svxlink.service, hvis en genindlæsning ikke ser ud til at få en ændring med (nogle indstillinger, som f.eks. hvilke logikkerner eller lydenheder der indlæses, kan kræve en fuld genstart).

Installation af en ældre version

Nyere versioner forbliver tilgængelige i poolen et stykke tid efter at være blevet afløst (dagligt i en uge, ugentligt i en måned, månedligt i et år — se »Retention« (opbevaring) i UPSTREAM-SYNC.MD), så et dårligt dagligt build normalt kan rulles tilbage. Pakker med upstream-udgivelser (komponenten release) fjernes aldrig:

apt list -a svxlink   # eller qtel; viser alle versioner, der stadig er i arkivet
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~deb13
sudo apt-mark hold svxlink   # valgfrit: forhindrer at "apt upgrade" opgraderer den igen
# sudo apt-mark unhold svxlink   # senere, for at genoptage automatiske opdateringer

Pakker

PakkeIndhold
svxlinkServerkomponenter (svxlink, remotetrx, svxreflector, logikkerner, Tcl-hændelsesscripts). Bygget med: RTL-SDR-understøttelse via direkte USB (medfølgende RTL-SDR Blog-fork af librtlsdr/rtl_tcp til aktuelle V3/V4-dongler; er i konflikt med distributionens librtlsdr0/rtl-sdr), den bidragne SipLogic-logikkerne (medfølgende PJSIP/pjproject, statisk linket), GPIO via libgpiod samt understøttelse af lydcodecs og plugins til Speex/Opus/LADSPA. Installerer en systemd-tjeneste. Indeholder ikke Qtel eller lydpakker. Indeholder en udev-regel, der giver SvxLink-tjenesten og brugere, der er logget ind på skrivebordet, adgang til RTL-SDR-USB-dongler.
qtelGrafisk EchoLink-klient (Qt6). Kræver et skrivebordsmiljø og svxlink-pakken i præcis samme version (deler dens echolib/async-biblioteker).

32-bit-systemer: armhf-pakker bygges mod Raspbian (ARMv6+VFP), grundlaget for 32-bit Raspberry Pi OS, så de kører på alle Raspberry Pi-modeller inklusive Pi 1, Zero og Zero W, og kan også installeres på Debian armhf (begge er testet). i386 (32-bit-pc'er) bygges kun til Debian 12: Debian 13 understøtter ikke længere installation af i386-systemer. 32-bit-pakkerne har de samme funktioner som 64-bit-pakkerne.

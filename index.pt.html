Repositório APT SvxLink DB9CR

⚠ Esta página foi traduzida automaticamente por inteligência artificial e pode conter erros. A versão em inglês é a que prevalece. (English)

Pacotes do svxlink-db9cr para Raspberry Pi OS e Debian, em dois componentes — escolha um:

  • main: compilações de desenvolvimento diárias a partir do código-fonte mais recente deste fork, não versões estáveis.
  • release: as versões oficiais do SvxLink original (upstream) (26.05 e posteriores), compiladas a partir do código-fonte upstream sem alterações, com as mesmas definições de compilação e funcionalidades dos pacotes diários. Todas as versões são mantidas; apt upgrade passa para cada nova versão upstream.

Consulte o repositório de código-fonte para mais pormenores.

Upstream e alterações locais

Este é um fork, sincronizado diariamente, de sm0svx/svxlink, o projeto SvxLink original, com empacotamento local e funcionalidades adicionais acrescentadas por cima (RTL-SDR, SipLogic, o pacote separado qtel, este repositório APT e mais — consulte CHANGELOG.MD para a lista completa). Para ver exatamente o que difere do upstream em qualquer momento, sem depender de um instantâneo aqui que fique desatualizado, compare em direto no GitHub: master upstream … master deste fork.

Início rápido

Execute no sistema de destino (deteta automaticamente o nome de código e a arquitetura corretos):

# Importar a chave pública de assinatura
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/svxlink-db9cr.gpg

# Adicionar a fonte do repositório. Escolha o componente:
#   main     compilações de desenvolvimento diárias
#   release  versões oficiais upstream (26.05 e posteriores)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Obrigatório antes do primeiro arranque: configure a sua estação, rádio e áudio.
# O ficheiro fornecido é apenas um modelo e tem de ser adaptado à sua instalação.
sudo editor /etc/svxlink/svxlink.conf

# Ativar o SvxLink no arranque do sistema e iniciá-lo agora.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Verificar o estado do serviço e acompanhar o seu registo.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Cliente EchoLink gráfico opcional (requer um ambiente de trabalho):
# sudo apt install qtel

Obrigatório: não inicie o serviço antes de editar /etc/svxlink/svxlink.conf. Configure pelo menos a identificação da estação, a lógica, o recetor/emissor e as definições de áudio/PTT para o seu hardware. O serviço lê este caminho através de /etc/default/svxlink.

Se apt update indicar um erro 404 para esta fonte, o nome de código do seu sistema ainda não é compilado (ver a tabela abaixo) — nesse caso, altere o nome de código em /etc/apt/sources.list.d/svxlink-db9cr.list para um dos suportados. Depois disso, um sudo apt upgrade regular obtém automaticamente as novas compilações diárias (main) ou as novas versões upstream (release).

Não ative os dois componentes ao mesmo tempo, a menos que pretenda as compilações diárias: têm sempre a versão mais alta, pelo que o apt instalá-las-ia por cima das versões oficiais. Para mudar uma instalação existente de main para release, altere o componente em /etc/apt/sources.list.d/svxlink-db9cr.list, execute sudo apt update e depois instale explicitamente a versão release (trata-se de um downgrade, ou seja, de uma versão inferior), por exemplo sudo apt install svxlink=26.05.2-1~trixie. Note que, nos pacotes release (código-fonte upstream sem alterações), os scripts TCL em /usr/share/svxlink não estão protegidos como ficheiros de configuração; mantenha as alterações locais em events.d/local/.

Aplicar alterações de configuração

Depois de editar /etc/svxlink/svxlink.conf (ou qualquer ficheiro de módulo /etc/svxlink/svxlink.d/*.conf) numa estação em funcionamento, recarregue a configuração sem interromper uma sessão ativa:

sudo systemctl reload svxlink.service

Isto envia o sinal SIGHUP, ao qual o SvxLink responde relendo a sua configuração. Use antes sudo systemctl restart svxlink.service se um recarregamento não parecer aplicar uma alteração (algumas definições, como os núcleos lógicos ou os dispositivos de som que são carregados, podem exigir um reinício completo).

Instalar uma versão anterior

As versões recentes continuam disponíveis no pool durante algum tempo depois de serem substituídas (uma por dia durante uma semana, uma por semana durante um mês, uma por mês durante um ano — ver «Retention» (retenção) em UPSTREAM-SYNC.MD), pelo que normalmente é possível reverter uma compilação diária defeituosa. Os pacotes das versões upstream (componente release) nunca são removidos:

apt list -a svxlink   # ou qtel; lista todas as versões ainda presentes no repositório
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~trixie
sudo apt-mark hold svxlink   # opcional: impede que o "apt upgrade" a volte a atualizar
# sudo apt-mark unhold svxlink   # mais tarde, para retomar as atualizações automáticas

Sistemas de 32 bits: os pacotes armhf são compilados para Raspbian (ARMv6+VFP), a base do Raspberry Pi OS de 32 bits, pelo que funcionam em todos os modelos de Raspberry Pi, incluindo o Pi 1, o Zero e o Zero W, e também se instalam no Debian armhf (ambos são testados). i386 (PC de 32 bits) só é compilado para o Debian 12: o Debian 13 já não suporta a instalação de sistemas i386. Os pacotes de 32 bits contêm as mesmas funcionalidades que os de 64 bits.

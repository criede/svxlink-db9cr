SvxLink DB9CR APT-Repository

⚠ Dës Säit gouf automatesch mat kënschtlecher Intelligenz iwwersat a ka Feeler enthalen. Déi englesch Versioun ass déi mossgeeblech. (English)

Pakete vun svxlink-db9cr fir Raspberry Pi OS an Debian, an zwou Komponenten — wielt der eng aus:

  • main: deeglech Entwécklungs-Builds aus dem neiste Quellcode vun dësem Fork, keng stabil Releases.
  • release: déi offiziell Upstream-Releases vu SvxLink (26.05 an méi nei), gebaut aus dem onverännerte Upstream-Release-Quellcode mat deene selwechte Build-Astellungen a Funktiounen wéi déi deeglech Paketen. All Release gëtt behalen; apt upgrade wiesselt all Kéier op dat neit Upstream-Release.

Detailer fannt Dir am Quellcode-Repository.

Upstream an lokal Ännerungen

Dëst ass en deeglech synchroniséierte Fork vun sm0svx/svxlink, dem ursprénglechen SvxLink-Projet, mat eegener Paketéierung an zousätzleche Funktiounen doriwwer (RTL-SDR, SipLogic, de separate Paket qtel, dëse APT-Repository a méi — déi komplett Lëscht steet an CHANGELOG.MD). Fir zu all Moment genee ze gesinn, wat sech vum Upstream ënnerscheet, ouni sech op eng Momentopnam hei ze verloossen, déi veralt, vergläicht live op GitHub: Upstream-master … master vun dësem Fork.

Séier Ufank

Um Zilsystem ausféieren (Codename an Architektur ginn automatesch erkannt):

# Den ëffentlechen Ënnerschrëftsschlëssel importéieren
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/svxlink-db9cr.gpg

# D'Repository-Quell derbäisetzen. Komponent wielen:
#   main     deeglech Entwécklungs-Builds
#   release  offiziell Upstream-Releases (26.05 a méi nei)
component=main
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Obligatoresch virum éischte Start: Statioun, Funkgerät an Audio konfiguréieren.
# De matgeliwwerte Fichier ass nëmmen eng Schabloun a muss un Är Installatioun ugepasst ginn.
sudo editor /etc/svxlink/svxlink.conf

# SvxLink beim Booten aktivéieren an elo starten.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Status vum Service kontrolléieren an de Log verfollegen.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Optionalen grafeschen EchoLink-Client (brauch eng Desktop-Ëmgebung):
# sudo apt install qtel

Obligatoresch: Startt de Service net, ier Dir /etc/svxlink/svxlink.conf beaarbecht hutt. Konfiguréiert op d'mannst d'Identitéit vun der Statioun, d'Logik, Empfänger/Sender an d'Audio-/PTT-Astellunge fir Är Hardware. De Service liest dëse Pfad iwwer /etc/default/svxlink.

Wann apt update fir dës Quell en 404 mellt, gëtt de Codename vun Ärem System nach net gebaut (kuckt d'Tabell hei ënnen) — ännert dann de Codename an /etc/apt/sources.list.d/svxlink-db9cr.list op ee vun deenen ënnerstëtzten. Duerno hëlt en normalt sudo apt upgrade automatesch nei deeglech Builds (main) oder nei Upstream-Releases (release).

Aktivéiert net béid Komponenten gläichzäiteg, ausser Dir wëllt déi deeglech Builds: Si hunn ëmmer déi méi héich Versioun, dofir géif apt se amplaz vun de Releases installéieren. Fir eng bestehend Installatioun vu main op release ëmzestellen, ännert de Komponent an /etc/apt/sources.list.d/svxlink-db9cr.list, féiert sudo apt update aus an installéiert dann d'Release-Versioun explizit (et ass en Downgrade), z. B. sudo apt install svxlink=26.05.2-1~trixie. Notéiert, datt an release-Paketen (onverännerten Upstream-Quellcode) d'TCL-Skripter ënner /usr/share/svxlink net als Konfiguratiounsfichiere geschützt sinn; leet lokal Ännerungen an events.d/local/ of.

Konfiguratiounsännerungen iwwerhuelen

Nodeems Dir /etc/svxlink/svxlink.conf (oder e Modulfichier /etc/svxlink/svxlink.d/*.conf) op enger lafender Statioun beaarbecht hutt, luet d'Konfiguratioun nei, ouni eng aktiv Sessioun ofzebriechen:

sudo systemctl reload svxlink.service

Dëst schéckt SIGHUP, op dat hin SvxLink seng Konfiguratioun nei aliest. Benotzt amplaz sudo systemctl restart svxlink.service, wann e Reload eng Ännerung schéngbar net iwwerhëlt (verschidden Astellungen, wéi zum Beispill wéi eng Logik-Kären oder Tounapparater geluede ginn, kënnen e komplette Restart brauchen).

Eng méi al Versioun installéieren

Rezent Versioune bleiwen nach eng Zäit am Pool disponibel, nodeems se ersat goufen (deeglech fir eng Woch, wöchentlech fir ee Mount, monatlech fir ee Joer — kuckt „Retention“ (Bewaardauer) an UPSTREAM-SYNC.MD), sou datt e schlechten deegleche Build normalerweis zréckgesat ka ginn. Pakete vun Upstream-Releases (Komponent release) ginn ni geläscht:

apt list -a svxlink   # oder qtel; weist all Versiounen, déi nach am Repository sinn
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~trixie
sudo apt-mark hold svxlink   # fakultativ: verhënnert, datt "apt upgrade" en erëm aktualiséiert
# sudo apt-mark unhold svxlink   # méi spéit, fir automatesch Updates erëm opzehuelen

Paketen

PaketInhalt
svxlinkServer-Komponenten (svxlink, remotetrx, svxreflector, Logik-Kären, Tcl-Event-Skripter). Gebaut mat: RTL-SDR-Ënnerstëtzung iwwer direkten USB (matgeliwwerte RTL-SDR-Blog-Fork vu librtlsdr/rtl_tcp fir aktuell V3/V4-Dongles; a Konflikt mat librtlsdr0/rtl-sdr vun der Distributioun), dem bäigesteierte SipLogic-Logik-Kär (matgeliwwert PJSIP/pjproject, statesch gelinkt), GPIO iwwer libgpiod an Ënnerstëtzung fir d'Audio-Codecen a Plugins Speex/Opus/LADSPA. Installéiert e systemd-Service. Enthält weder Qtel nach Sproochpaketen.
qtelGrafeschen EchoLink-Client (Qt6). Brauch eng Desktop-Ëmgebung an de Paket svxlink an exakt der selwechter Versioun (benotzt seng echolib/async-Bibliothéiken).

32-Bit-Systemer: armhf-Pakete ginn géint Raspbian (ARMv6+VFP) gebaut, d'Basis vum 32-Bit-Raspberry-Pi-OS, sou datt se op all Raspberry-Pi-Modell lafen, inklusiv Pi 1, Zero an Zero W, a sech och op Debian armhf installéiere loossen (béides ass getest). i386 (32-Bit-PCen) gëtt nëmme fir Debian 12 gebaut: Debian 13 ënnerstëtzt d'Installatioun vun i386-Systemer net méi. D'32-Bit-Pakete bidden déi selwecht Funktiounen wéi d'64-Bit-Paketen.

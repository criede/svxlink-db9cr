SvxLink DB9CR -APT-pakettivarasto

⚠ Tämä sivu on käännetty automaattisesti tekoälyllä, ja se voi sisältää virheitä. Englanninkielinen versio on määräävä. (English)

Projektin svxlink-db9cr paketit Raspberry Pi OS:lle ja Debianille kahtena komponenttina — valitse niistä yksi:

  • main: päivittäiset kehitysversiot tämän forkin uusimmasta lähdekoodista, eivät vakaita julkaisuja.
  • release: viralliset upstream-SvxLink-julkaisut (26.05 ja uudemmat), käännetty muuttamattomasta upstream-julkaisun lähdekoodista samoilla käännösasetuksilla ja ominaisuuksilla kuin päivittäiset paketit. Kaikki julkaisut säilytetään; apt upgrade siirtyy jokaiseen uuteen upstream-julkaisuun.

Lisätietoja on lähdekoodivarastossa.

Upstream ja paikalliset muutokset

Tämä on päivittäin synkronoitu fork projektista sm0svx/svxlink, joka on alkuperäinen SvxLink-projekti, ja sen päälle on lisätty paikallisia paketointeja ja ominaisuuksia (RTL-SDR, SipLogic, erillinen qtel-paketti, tämä APT-varasto ja muuta — täydellinen luettelo on tiedostossa CHANGELOG.MD). Jos haluat nähdä tarkalleen, mikä eroaa upstreamista minä tahansa hetkenä, ilman että täällä oleva tilannekuva vanhenee, vertaa suoraan GitHubissa: upstreamin master … tämän forkin master.

Pika-aloitus

Suorita kohdejärjestelmässä (tunnistaa oikean koodinimen/arkkitehtuurin automaattisesti):

# Tuo julkinen allekirjoitusavain
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/svxlink-db9cr.gpg

# Lisää varastolähde. Valitse komponentti:
#   main     päivittäiset kehitysversiot
#   release  viralliset upstream-julkaisut (26.05 ja uudemmat)
component=main
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Pakollinen ennen ensimmäistä käynnistystä: määritä asemasi, radiosi ja äänilaitteet.
# Paketin mukana tuleva tiedosto on vain malli, ja se on mukautettava omaan kokoonpanoosi.
sudo editor /etc/svxlink/svxlink.conf

# Ota SvxLink käyttöön käynnistyksen yhteydessä ja käynnistä se heti.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Tarkista palvelun tila ja seuraa sen lokia.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Valinnainen graafinen EchoLink-asiakasohjelma (vaatii työpöytäympäristön):
# sudo apt install qtel

Pakollista: Älä käynnistä palvelua ennen kuin olet muokannut tiedostoa /etc/svxlink/svxlink.conf. Määritä vähintään aseman tunniste, logiikka, vastaanotin/lähetin sekä ääni- ja PTT-asetukset laitteistosi mukaan. Palvelu lukee tämän polun tiedoston /etc/default/svxlink kautta.

Jos apt update ilmoittaa tälle lähteelle virheen 404, järjestelmäsi koodinimelle ei vielä käännetä paketteja (katso alla oleva taulukko) — vaihda tiedostossa /etc/apt/sources.list.d/svxlink-db9cr.list koodinimeksi jokin tuetuista. Sen jälkeen tavallinen sudo apt upgrade hakee uudet päivittäiset versiot (main) tai uudet upstream-julkaisut (release) automaattisesti.

Älä ota molempia komponentteja käyttöön samanaikaisesti, ellet halua päivittäisiä versioita: niillä on aina korkeampi versionumero, joten apt asentaisi ne julkaisujen päälle. Jos haluat vaihtaa olemassa olevan asennuksen komponentista main komponenttiin release, vaihda komponentti tiedostossa /etc/apt/sources.list.d/svxlink-db9cr.list, suorita sudo apt update ja asenna sitten julkaisuversio erikseen (kyseessä on paluu vanhempaan versioon eli downgrade), esim. sudo apt install svxlink=26.05.2-1~trixie. Huomaa, että release-paketeissa (muuttamaton upstream-lähdekoodi) hakemiston /usr/share/svxlink TCL-skriptejä ei ole suojattu asetustiedostoina; säilytä paikalliset muutokset hakemistossa events.d/local/.

Asetusmuutosten käyttöönotto

Kun olet muokannut tiedostoa /etc/svxlink/svxlink.conf (tai mitä tahansa /etc/svxlink/svxlink.d/*.conf-moduulitiedostoa) käynnissä olevalla asemalla, lataa asetukset uudelleen katkaisematta aktiivista istuntoa:

sudo systemctl reload svxlink.service

Tämä lähettää signaalin SIGHUP, jonka saatuaan SvxLink lukee asetuksensa uudelleen. Käytä sen sijaan komentoa sudo systemctl restart svxlink.service, jos uudelleenlataus ei näytä ottavan muutosta käyttöön (jotkin asetukset, kuten ladattavat logiikkaytimet tai äänilaitteet, voivat vaatia täyden uudelleenkäynnistyksen).

Vanhemman version asentaminen

Viimeaikaiset versiot pysyvät saatavilla poolissa jonkin aikaa sen jälkeen, kun uudempi on korvannut ne (päivittäiset viikon ajan, viikoittaiset kuukauden ajan, kuukausittaiset vuoden ajan — katso kohta "Retention" (säilytys) tiedostossa UPSTREAM-SYNC.MD), joten huonon päivittäisen version voi yleensä perua. Upstream-julkaisupaketteja (release-komponentti) ei koskaan poisteta:

apt list -a svxlink   # tai qtel; näyttää kaikki arkistossa vielä olevat versiot
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~trixie
sudo apt-mark hold svxlink   # valinnainen: estää "apt upgrade" -komentoa päivittämästä sitä uudelleen
# sudo apt-mark unhold svxlink   # myöhemmin, kun haluat jatkaa automaattisia päivityksiä

Paketit

PakettiSisältö
svxlinkPalvelinkomponentit (svxlink, remotetrx, svxreflector, logiikkaytimet, Tcl-tapahtumaskriptit). Käännetty seuraavilla: RTL-SDR-tuki suoraan USB:n kautta (mukana RTL-SDR Blogin librtlsdr/rtl_tcp-fork nykyisille V3/V4-dongleille; on ristiriidassa jakelun librtlsdr0/rtl-sdr-pakettien kanssa), yhteisön tuottama SipLogic-logiikkaydin (mukana PJSIP/pjproject, staattisesti linkitetty), GPIO libgpiodin kautta sekä Speex/Opus/LADSPA-äänikoodekki- ja liitännäistuki. Asentaa systemd-palvelun. Ei sisällä Qteliä eikä äänipaketteja.
qtelGraafinen EchoLink-asiakasohjelma (Qt6). Vaatii työpöytäympäristön ja täsmälleen saman version svxlink-paketista (käyttää sen echolib/async-kirjastoja).

32-bittiset järjestelmät: armhf-paketit käännetään Raspbiania (ARMv6+VFP) vasten, joka on 32-bittisen Raspberry Pi OS:n perusta, joten ne toimivat kaikissa Raspberry Pi -malleissa, myös Pi 1:ssä, Zerossa ja Zero W:ssä, ja ne voi asentaa myös Debianin armhf-järjestelmään (molemmat on testattu). i386 (32-bittiset PC:t) käännetään vain Debian 12:lle: Debian 13 ei enää tue i386-järjestelmien asentamista. 32-bittisissä paketeissa on samat ominaisuudet kuin 64-bittisissä.

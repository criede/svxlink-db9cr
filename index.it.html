Repository APT SvxLink DB9CR

⚠ Questa pagina è stata tradotta automaticamente con l’intelligenza artificiale e può contenere errori. Fa fede la versione inglese. (English)

Pacchetti di svxlink-db9cr per Raspberry Pi OS e Debian, in due componenti — scegline uno:

  • main: build di sviluppo giornaliere dai sorgenti più recenti di questo fork, non versioni stabili.
  • release: le versioni ufficiali di SvxLink upstream (26.05 e successive), compilate dai sorgenti upstream non modificati con le stesse impostazioni di compilazione e funzionalità dei pacchetti giornalieri. Ogni versione viene conservata; apt upgrade passa a ogni nuova versione upstream.

Consulta il repository dei sorgenti per i dettagli.

Upstream e modifiche locali

Questo è un fork, sincronizzato quotidianamente, di sm0svx/svxlink, il progetto SvxLink originale, con pacchettizzazione locale e funzionalità aggiuntive aggiunte sopra (RTL-SDR, SipLogic, il pacchetto separato qtel, questo repository APT e altro ancora — vedere CHANGELOG.MD per l'elenco completo). Per vedere esattamente cosa differisce da upstream in qualsiasi momento, senza affidarsi a un'istantanea che qui diventerebbe obsoleta, confronta in tempo reale su GitHub: master upstream … master di questo fork.

Avvio rapido

Esegui sul sistema di destinazione (rileva automaticamente il nome in codice e l'architettura corretti):

# Importare la chiave pubblica di firma
# (viene accettata solo la chiave con questa impronta: E9CF E946 7D00 3148 AB93  EBAC 4ED4 4F53 51D8 1844)
tmp=$(mktemp -d)
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | gpg --quiet --homedir "$tmp" --import
gpg --homedir "$tmp" --export E9CFE9467D003148AB93EBAC4ED44F5351D81844 | \
  sudo tee /usr/share/keyrings/svxlink-db9cr.gpg >/dev/null
rm -rf "$tmp"

# Aggiungere la sorgente del repository. Scegli il componente:
#   main     build di sviluppo giornaliere
#   release  versioni ufficiali upstream (26.05 e successive)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Obbligatorio prima del primo avvio: configura stazione, radio e audio.
# Il file fornito è solo un modello e deve essere adattato alla tua configurazione.
sudo editor /etc/svxlink/svxlink.conf

# Abilitare SvxLink all'avvio del sistema e avviarlo subito.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Controllare lo stato del servizio e seguirne il log.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Client EchoLink grafico opzionale (richiede un ambiente desktop):
# sudo apt install qtel

Obbligatorio: non avviare il servizio prima di aver modificato /etc/svxlink/svxlink.conf. Configura almeno l'identità della stazione, la logica, ricevitore/trasmettitore e le impostazioni audio/PTT per il tuo hardware. Il servizio legge questo percorso tramite /etc/default/svxlink.

Se apt update segnala un errore 404 per questa sorgente, il nome in codice del tuo sistema non viene ancora compilato (vedere la tabella sotto) — in tal caso modifica il nome in codice in /etc/apt/sources.list.d/svxlink-db9cr.list in uno di quelli supportati. Successivamente, un normale sudo apt upgrade installa automaticamente le nuove build giornaliere (main) o le nuove versioni upstream (release).

Non abilitare entrambi i componenti contemporaneamente, a meno che tu non voglia le build giornaliere: hanno sempre la versione più alta, quindi apt le installerebbe al posto delle versioni ufficiali. Per passare un'installazione esistente da main a release, cambia il componente in /etc/apt/sources.list.d/svxlink-db9cr.list, esegui sudo apt update, quindi installa esplicitamente la versione release (si tratta di un downgrade), ad es. sudo apt install svxlink=26.05.2-2~deb13. Tieni presente che nei pacchetti release (sorgenti upstream non modificati) gli script TCL in /usr/share/svxlink non sono protetti come file di configurazione; mantieni le modifiche locali in events.d/local/.

Applicare modifiche alla configurazione

Dopo aver modificato /etc/svxlink/svxlink.conf (o un qualsiasi file di modulo /etc/svxlink/svxlink.d/*.conf) su una stazione in funzione, ricarica la configurazione senza interrompere una sessione attiva:

sudo systemctl reload svxlink.service

Questo invia il segnale SIGHUP, alla ricezione del quale SvxLink rilegge la propria configurazione. Usa invece sudo systemctl restart svxlink.service se un ricaricamento non sembra recepire una modifica (alcune impostazioni, come quali core logici o dispositivi audio vengono caricati, possono richiedere un riavvio completo).

Installare una versione precedente

Le versioni recenti restano disponibili nel pool per un certo periodo dopo essere state sostituite (una al giorno per una settimana, una alla settimana per un mese, una al mese per un anno — vedere «Retention» (conservazione) in UPSTREAM-SYNC.MD), quindi di solito è possibile tornare indietro da una build giornaliera difettosa. I pacchetti delle versioni upstream (componente release) non vengono mai rimossi:

apt list -a svxlink   # o qtel; elenca tutte le versioni ancora presenti nel repository
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~deb13
sudo apt-mark hold svxlink   # facoltativo: impedisce che "apt upgrade" la aggiorni di nuovo
# sudo apt-mark unhold svxlink   # in seguito, per riprendere gli aggiornamenti automatici

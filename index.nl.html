SvxLink DB9CR APT-repository

⚠ Deze pagina is automatisch vertaald met kunstmatige intelligentie en kan fouten bevatten. De Engelse versie is leidend. (English)

Pakketten van svxlink-db9cr voor Raspberry Pi OS en Debian, in twee componenten — kies er één:

  • main: dagelijkse ontwikkelbuilds van de nieuwste broncode van deze fork, geen stabiele releases.
  • release: de officiële upstream-releases van SvxLink (26.05 en nieuwer), gebouwd uit de ongewijzigde upstream-releasebroncode met dezelfde build-instellingen en functies als de dagelijkse pakketten. Elke release blijft bewaard; apt upgrade stapt telkens over op de nieuwe upstream-release.

Zie de broncode-repository voor details.

Upstream en lokale wijzigingen

Dit is een dagelijks gesynchroniseerde fork van sm0svx/svxlink, het oorspronkelijke SvxLink-project, met eigen packaging en extra functies daarbovenop (RTL-SDR, SipLogic, het aparte pakket qtel, deze APT-repository en meer — zie CHANGELOG.MD voor de volledige lijst). Om op elk moment precies te zien wat er anders is dan upstream, zonder te vertrouwen op een momentopname hier die veroudert, kun je live vergelijken op GitHub: upstream master … master van deze fork.

Snel aan de slag

Uit te voeren op het doelsysteem (detecteert automatisch de juiste codenaam/architectuur):

# De publieke ondertekeningssleutel importeren
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/svxlink-db9cr.gpg

# De repository-bron toevoegen. Kies de component:
#   main     dagelijkse ontwikkelbuilds
#   release  officiële upstream-releases (26.05 en nieuwer)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Verplicht vóór de eerste start: configureer je station, zender/ontvanger en audio.
# Het meegeleverde bestand is slechts een sjabloon en moet aan je opstelling worden aangepast.
sudo editor /etc/svxlink/svxlink.conf

# SvxLink bij het opstarten inschakelen en nu starten.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Status van de service controleren en het log volgen.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Optionele grafische EchoLink-client (vereist een desktopomgeving):
# sudo apt install qtel

Vereist: start de service niet voordat je /etc/svxlink/svxlink.conf hebt bewerkt. Configureer ten minste de stationsidentiteit, logica, ontvanger/zender en de audio-/PTT-instellingen voor je hardware. De service leest dit pad via /etc/default/svxlink.

Als apt update een 404 meldt voor deze bron, wordt de codenaam van je systeem nog niet gebouwd (zie de tabel hieronder) — wijzig dan de codenaam in /etc/apt/sources.list.d/svxlink-db9cr.list in een van de ondersteunde. Daarna haalt een gewone sudo apt upgrade automatisch nieuwe dagelijkse builds (main) of nieuwe upstream-releases (release) op.

Schakel niet beide componenten tegelijk in, tenzij je de dagelijkse builds wilt: die hebben altijd de hogere versie, dus apt zou ze installeren in plaats van de releases. Om een bestaande installatie van main naar release om te zetten, wijzig je de component in /etc/apt/sources.list.d/svxlink-db9cr.list, voer je sudo apt update uit en installeer je daarna expliciet de releaseversie (het is een downgrade), bijv. sudo apt install svxlink=26.05.2-1~trixie. Let op: in release-pakketten (ongewijzigde upstream-broncode) zijn de TCL-scripts onder /usr/share/svxlink niet beschermd als configuratiebestanden; bewaar lokale wijzigingen in events.d/local/.

Configuratiewijzigingen toepassen

Na het bewerken van /etc/svxlink/svxlink.conf (of een modulebestand /etc/svxlink/svxlink.d/*.conf) op een draaiend station herlaad je de configuratie zonder een actieve sessie te verbreken:

sudo systemctl reload svxlink.service

Dit verstuurt SIGHUP, waarop SvxLink zijn configuratie opnieuw inleest. Gebruik in plaats daarvan sudo systemctl restart svxlink.service als een reload een wijziging niet lijkt over te nemen (sommige instellingen, zoals welke logic cores of geluidsapparaten worden geladen, kunnen een volledige herstart vereisen).

Een oudere versie installeren

Recente versies blijven nog een tijd in de pool beschikbaar nadat ze zijn vervangen (dagelijks gedurende een week, wekelijks gedurende een maand, maandelijks gedurende een jaar — zie "Retention" (bewaarbeleid) in UPSTREAM-SYNC.MD), zodat een slechte dagelijkse build meestal kan worden teruggedraaid. Pakketten van upstream-releases (component release) worden nooit verwijderd:

apt list -a svxlink   # of qtel; toont alle versies die nog in de repository staan
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~trixie
sudo apt-mark hold svxlink   # optioneel: voorkomt dat "apt upgrade" hem weer bijwerkt
# sudo apt-mark unhold svxlink   # later, om automatische updates te hervatten

Pakketten

PakketInhoud
svxlinkServercomponenten (svxlink, remotetrx, svxreflector, logic cores, Tcl-eventscripts). Gebouwd met: RTL-SDR-ondersteuning via directe USB (meegeleverde RTL-SDR Blog-fork van librtlsdr/rtl_tcp voor huidige V3/V4-dongles; conflicteert met librtlsdr0/rtl-sdr van de distributie), de bijgedragen SipLogic logic core (meegeleverd PJSIP/pjproject, statisch gelinkt), GPIO via libgpiod, en ondersteuning voor de audiocodecs en plug-ins Speex/Opus/LADSPA. Installeert een systemd-service. Bevat geen Qtel en geen geluidspakketten.
qtelGrafische EchoLink-client (Qt6). Vereist een desktopomgeving en het pakket svxlink van precies dezelfde versie (deelt de echolib/async-bibliotheken daarvan).

32-bitsystemen: armhf-pakketten worden gebouwd tegen Raspbian (ARMv6+VFP), de basis van 32-bit Raspberry Pi OS, zodat ze draaien op elk Raspberry Pi-model, inclusief de Pi 1, Zero en Zero W, en ook te installeren zijn op Debian armhf (beide zijn getest). i386 (32-bit pc's) wordt alleen gebouwd voor Debian 12: Debian 13 ondersteunt de installatie van i386-systemen niet meer. De 32-bitpakketten bevatten dezelfde functies als de 64-bitpakketten.

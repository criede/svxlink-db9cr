APT-рэпазіторый SvxLink DB9CR

⚠ Гэтая старонка перакладзена аўтаматычна з дапамогай штучнага інтэлекту і можа ўтрымліваць памылкі. Вызначальнай з’яўляецца англійская версія. (English)

Пакеты svxlink-db9cr для Raspberry Pi OS і Debian у двух кампанентах — выберы адзін:

  • main: штодзённыя зборкі для распрацоўкі з найноўшага зыходнага кода гэтага форка, а не стабільныя выпускі.
  • release: афіцыйныя выпускі SvxLink з upstream (26.05 і навейшыя), сабраныя з нязменнага зыходнага кода выпуску upstream з тымі ж параметрамі зборкі і функцыямі, што і штодзённыя пакеты. Кожны выпуск захоўваецца; apt upgrade пераходзіць на кожны новы выпуск upstream.

Падрабязнасці глядзі ў рэпазіторыі зыходнага кода.

Upstream і лакальныя змены

Гэта штодзённа сінхранізаваны форк sm0svx/svxlink, арыгінальнага праекта SvxLink, з лакальным пакаваннем і дадатковымі функцыямі па-над ім (RTL-SDR, SipLogic, асобны пакет qtel, гэты APT-рэпазіторый і іншае — поўны пералік глядзі ў CHANGELOG.MD). Каб у любы момант дакладна ўбачыць, чым форк адрозніваецца ад upstream, не спадзеючыся на здымак тут, які можа састарэць, параўнай актуальны стан на GitHub: upstream master … master гэтага форка.

Хуткі старт

Выканай на мэтавай сістэме (патрэбныя кодавая назва і архітэктура вызначаюцца аўтаматычна):

# Імпарт адкрытага ключа подпісу
# (прымаецца толькі ключ з гэтым адбіткам: E9CF E946 7D00 3148 AB93  EBAC 4ED4 4F53 51D8 1844)
tmp=$(mktemp -d)
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | gpg --quiet --homedir "$tmp" --import
gpg --homedir "$tmp" --export E9CFE9467D003148AB93EBAC4ED44F5351D81844 | \
  sudo tee /usr/share/keyrings/svxlink-db9cr.gpg >/dev/null
rm -rf "$tmp"

# Даданне крыніцы рэпазіторыя. Выберы кампанент:
#   main     штодзённыя зборкі для распрацоўкі
#   release  афіцыйныя выпускі upstream (26.05 і навейшыя)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Абавязкова перад першым запускам: наладзь станцыю, радыёстанцыю і аўдыя.
# Файл з пакета з’яўляецца толькі шаблонам і павінен быць адаптаваны да тваёй канфігурацыі.
sudo editor /etc/svxlink/svxlink.conf

# Уключыць запуск SvxLink пры загрузцы сістэмы і запусціць яго зараз.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Праверыць стан службы і сачыць за яе журналам.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Неабавязковы графічны кліент EchoLink (патрабуецца асяроддзе працоўнага стала):
# sudo apt install qtel

Абавязкова: Не запускай службу да рэдагавання /etc/svxlink/svxlink.conf. Наладзь прынамсі ідэнтыфікацыю станцыі, логіку, прыёмнік/перадатчык і параметры аўдыя/PTT для твайго абсталявання. Служба атрымлівае гэты шлях праз /etc/default/svxlink.

Калі apt update паведамляе пра памылку 404 для гэтай крыніцы, для кодавай назвы тваёй сістэмы яшчэ няма зборак (глядзі табліцу ніжэй) — замест гэтага змяні кодавую назву ў /etc/apt/sources.list.d/svxlink-db9cr.list на адну з падтрымліваемых. Пасля гэтага звычайная каманда sudo apt upgrade аўтаматычна атрымлівае новыя штодзённыя зборкі (main) або новыя выпускі upstream (release).

Не ўключай абодва кампаненты адначасова, калі толькі табе не патрэбныя штодзённыя зборкі: яны заўсёды маюць вышэйшую версію, таму apt усталяваў бы іх замест выпускаў. Каб перавесці існуючую ўсталёўку з main на release, змяні кампанент у /etc/apt/sources.list.d/svxlink-db9cr.list, выканай sudo apt update, а потым яўна ўсталюй версію выпуску (гэта паніжэнне версіі), напрыклад sudo apt install svxlink=26.05.2-1~trixie. Звярні ўвагу, што ў пакетах release (нязменны зыходны код upstream) скрыпты TCL у /usr/share/svxlink не абаронены як канфігурацыйныя файлы; захоўвай лакальныя змены ў events.d/local/.

Ужыванне змен канфігурацыі

Пасля рэдагавання /etc/svxlink/svxlink.conf (або любога файла модуля /etc/svxlink/svxlink.d/*.conf) на працуючай станцыі перазагрузі канфігурацыю без разрыву актыўнага сеанса:

sudo systemctl reload svxlink.service

Гэтая каманда адпраўляе SIGHUP, па якім SvxLink паўторна счытвае сваю канфігурацыю. Замест гэтага выкарыстоўвай sudo systemctl restart svxlink.service, калі перазагрузка, здаецца, не ўжывае змену (некаторыя параметры, напрыклад, якія ядры логікі ці гукавыя прылады загружаюцца, могуць патрабаваць поўнага перазапуску).

Усталёўка старэйшай версіі

Нядаўнія версіі застаюцца даступнымі ў пуле (pool) яшчэ некаторы час пасля замены навейшымі (штодзённыя на працягу тыдня, штотыднёвыя на працягу месяца, штомесячныя на працягу года — глядзі раздзел «Retention» (захоўванне) у UPSTREAM-SYNC.MD), таму няўдалую штодзённую зборку звычайна можна адкаціць. Пакеты выпускаў upstream (кампанент release) ніколі не выдаляюцца:

apt list -a svxlink   # або qtel; паказвае ўсе версіі, якія яшчэ ёсць у рэпазітарыі
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~trixie
sudo apt-mark hold svxlink   # неабавязкова: не дае "apt upgrade" зноў яе абнавіць
# sudo apt-mark unhold svxlink   # пазней, каб аднавіць аўтаматычныя абнаўленні

Пакеты

ПакетЗмест
svxlinkСерверныя кампаненты (svxlink, remotetrx, svxreflector, ядры логікі, скрыпты падзей Tcl). Сабраны з: падтрымкай RTL-SDR праз прамое USB-падключэнне (убудаваны форк librtlsdr/rtl_tcp ад RTL-SDR Blog для сучасных донглаў V3/V4; канфліктуе з пакетамі дыстрыбутыва librtlsdr0/rtl-sdr), прадастаўленым супольнасцю ядром логікі SipLogic (убудаваны PJSIP/pjproject, статычна скампанаваны), GPIO праз libgpiod і падтрымкай аўдыякодэкаў і плагінаў Speex/Opus/LADSPA. qtelГрафічны кліент EchoLink (Qt6). Патрабуе асяроддзя працоўнага стала і пакета svxlink дакладна той жа версіі (выкарыстоўвае яго бібліятэкі echolib/async).

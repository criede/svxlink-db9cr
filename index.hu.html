SvxLink DB9CR APT-tároló

⚠ Ezt az oldalt mesterséges intelligencia fordította automatikusan, ezért hibákat tartalmazhat. Az angol változat az irányadó. (English)

Az svxlink-db9cr csomagjai Raspberry Pi OS és Debian rendszerekhez, két komponensben — válassz egyet:

  • main: napi fejlesztői buildek ennek a forknak a legfrissebb forráskódjából, nem stabil kiadások.
  • release: a hivatalos upstream SvxLink-kiadások (26.05 és újabbak), a módosítatlan upstream kiadási forráskódból fordítva, a napi csomagokkal azonos build-beállításokkal és funkciókkal. Minden kiadás megmarad; az apt upgrade minden új upstream kiadásra frissít.

A részletekért lásd a forráskód-tárolót.

Upstream és helyi módosítások

Ez az sm0svx/svxlink, az eredeti SvxLink projekt naponta szinkronizált forkja, amelyre helyi csomagolás és funkcióbővítések épülnek (RTL-SDR, SipLogic, a különálló qtel csomag, ez az APT-tároló és egyebek — a teljes listát lásd a CHANGELOG.MD fájlban). Ha bármely időpontban pontosan látni szeretnéd, miben tér el a fork az upstreamtől, anélkül hogy egy itt elavuló pillanatképre hagyatkoznál, hasonlítsd össze élőben a GitHubon: upstream master … e fork mastere.

Gyors kezdés

Futtasd a célrendszeren (automatikusan felismeri a megfelelő kódnevet/architektúrát):

# A nyilvános aláírókulcs importálása
# (csak az ezzel az ujjlenyomattal rendelkező kulcsot fogadja el: E9CF E946 7D00 3148 AB93  EBAC 4ED4 4F53 51D8 1844)
tmp=$(mktemp -d)
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | gpg --quiet --homedir "$tmp" --import
gpg --homedir "$tmp" --export E9CFE9467D003148AB93EBAC4ED44F5351D81844 | \
  sudo tee /usr/share/keyrings/svxlink-db9cr.gpg >/dev/null
rm -rf "$tmp"

# A tárolóforrás hozzáadása. Válaszd ki a komponenst:
#   main     napi fejlesztői buildek
#   release  hivatalos upstream kiadások (26.05 és újabbak)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Kötelező az első indítás előtt: konfiguráld az állomást, a rádiót és a hangot.
# A csomagban lévő fájl csak sablon, és a saját összeállításodhoz kell igazítani.
sudo editor /etc/svxlink/svxlink.conf

# Az SvxLink engedélyezése rendszerindításkor és azonnali elindítása.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# A szolgáltatás állapotának ellenőrzése és naplójának követése.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Opcionális grafikus EchoLink-kliens (asztali környezetet igényel):
# sudo apt install qtel

Kötelező: Ne indítsd el a szolgáltatást, mielőtt szerkesztenéd a /etc/svxlink/svxlink.conf fájlt. Állítsd be legalább az állomásazonosítót, a logikát, a vevő/adó és a hang/PTT beállításait a hardveredhez. A szolgáltatás ezt az elérési utat a /etc/default/svxlink fájlon keresztül kapja meg.

Ha az apt update 404-es hibát jelez ennél a forrásnál, a rendszered kódnevéhez még nem készülnek csomagok (lásd az alábbi táblázatot) — ehelyett írd át a kódnevet a /etc/apt/sources.list.d/svxlink-db9cr.list fájlban az egyik támogatottra. Ezt követően egy szokásos sudo apt upgrade automatikusan telepíti az új napi buildeket (main) vagy az új upstream kiadásokat (release).

Ne engedélyezd egyszerre mindkét komponenst, hacsak nem a napi buildeket szeretnéd: ezeknek mindig magasabb a verziószáma, így az apt ezeket telepítené a kiadások helyett. Egy meglévő telepítés main komponensről release komponensre váltásához módosítsd a komponenst a /etc/apt/sources.list.d/svxlink-db9cr.list fájlban, futtasd a sudo apt update parancsot, majd telepítsd kifejezetten a kiadási verziót (ez visszalépés egy alacsonyabb verzióra, azaz downgrade), pl. sudo apt install svxlink=26.05.2-1~trixie. Vedd figyelembe, hogy a release csomagokban (módosítatlan upstream forráskód) a /usr/share/svxlink alatti TCL-szkriptek nincsenek konfigurációs fájlként védve; a helyi módosításokat tartsd az events.d/local/ könyvtárban.

Konfigurációs módosítások alkalmazása

Ha futó állomáson szerkesztetted a /etc/svxlink/svxlink.conf fájlt (vagy bármely /etc/svxlink/svxlink.d/*.conf modulfájlt), töltsd be újra a konfigurációt egy aktív munkamenet megszakítása nélkül:

sudo systemctl reload svxlink.service

Ez SIGHUP jelet küld, amelynek hatására az SvxLink újraolvassa a konfigurációját. Ha az újratöltés után egy módosítás nem tűnik érvényesnek, használd helyette a sudo systemctl restart svxlink.service parancsot (egyes beállítások, például hogy mely logikamagok vagy hangeszközök töltődnek be, teljes újraindítást igényelhetnek).

Régebbi verzió telepítése

A legutóbbi verziók a felváltásuk után még egy ideig elérhetők maradnak a poolban (napi bontásban egy hétig, heti bontásban egy hónapig, havi bontásban egy évig — lásd a „Retention” (megőrzés) részt az UPSTREAM-SYNC.MD fájlban), így egy hibás napi build általában visszaállítható. Az upstream kiadási csomagok (release komponens) soha nem kerülnek eltávolításra:

apt list -a svxlink   # vagy qtel; kilistázza a tárolóban még elérhető összes verziót
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~trixie
sudo apt-mark hold svxlink   # opcionális: megakadályozza, hogy az "apt upgrade" újra frissítse
# sudo apt-mark unhold svxlink   # később, az automatikus frissítések folytatásához

Csomagok

CsomagTartalom
svxlinkSzerverkomponensek (svxlink, remotetrx, svxreflector, logikamagok, Tcl-eseményszkriptek). Beépített funkciók: RTL-SDR közvetlen USB-támogatás (mellékelt RTL-SDR Blog librtlsdr/rtl_tcp fork a jelenlegi V3/V4 dongle-okhoz; ütközik a disztribúció librtlsdr0/rtl-sdr csomagjaival), a külső hozzájárulásként készült SipLogic logikamag (mellékelt PJSIP/pjproject, statikusan linkelve), GPIO a libgpiod segítségével, valamint Speex/Opus/LADSPA hangkodek- és bővítménytámogatás. Telepít egy systemd szolgáltatást. Nem tartalmazza a Qtel programot és a hangcsomagokat. Tartalmaz egy udev-szabályt, amely hozzáférést ad az RTL-SDR USB-donglékhoz a SvxLink szolgáltatásnak és az asztali munkamenetbe bejelentkezett felhasználóknak.
qtelGrafikus EchoLink-kliens (Qt6). Asztali környezetet és pontosan azonos verziójú svxlink csomagot igényel (közösen használja annak echolib/async könyvtárait).

32 bites rendszerek: az armhf csomagok a Raspbian (ARMv6+VFP) alapján készülnek, amely a 32 bites Raspberry Pi OS alapja, így minden Raspberry Pi modellen futnak, beleértve a Pi 1, a Zero és a Zero W modellt is, és Debian armhf rendszerre is telepíthetők (mindkettő tesztelve). Az i386 (32 bites PC-k) csak Debian 12-höz készül: a Debian 13 már nem támogatja i386 rendszerek telepítését. A 32 bites csomagok ugyanazokat a funkciókat tartalmazzák, mint a 64 bitesek.

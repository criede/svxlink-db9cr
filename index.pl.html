Repozytorium APT SvxLink DB9CR

⚠ Ta strona została przetłumaczona automatycznie przy użyciu sztucznej inteligencji i może zawierać błędy. Wiążąca jest wersja angielska. (English)

Pakiety svxlink-db9cr dla Raspberry Pi OS i Debiana, w dwóch komponentach — wybierz jeden:

  • main: codzienne kompilacje rozwojowe z najnowszego kodu źródłowego tego forka, a nie stabilne wydania.
  • release: oficjalne wydania SvxLink z projektu macierzystego (26.05 i nowsze), zbudowane z niezmienionego kodu źródłowego wydania z tymi samymi ustawieniami kompilacji i funkcjami co pakiety codzienne. Każde wydanie jest zachowywane; apt upgrade przechodzi na każde nowe wydanie projektu macierzystego.

Szczegóły znajdziesz w repozytorium źródłowym.

Projekt macierzysty i zmiany lokalne

To codziennie synchronizowany fork sm0svx/svxlink, oryginalnego projektu SvxLink, z dodanym na wierzchu własnym pakietowaniem i rozszerzeniami funkcji (RTL-SDR, SipLogic, osobny pakiet qtel, to repozytorium APT i więcej — pełna lista w CHANGELOG.MD). Aby w dowolnym momencie zobaczyć dokładnie, czym fork różni się od projektu macierzystego, bez polegania na nieaktualnym zrzucie w tym miejscu, porównaj na żywo w serwisie GitHub: master projektu macierzystego … master tego forka.

Szybki start

Uruchom w systemie docelowym (właściwa nazwa kodowa i architektura są wykrywane automatycznie):

# Zaimportuj publiczny klucz podpisujący
# (akceptowany jest tylko klucz z tym odciskiem: E9CF E946 7D00 3148 AB93  EBAC 4ED4 4F53 51D8 1844)
tmp=$(mktemp -d)
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | gpg --quiet --homedir "$tmp" --import
gpg --homedir "$tmp" --export E9CFE9467D003148AB93EBAC4ED44F5351D81844 | \
  sudo tee /usr/share/keyrings/svxlink-db9cr.gpg >/dev/null
rm -rf "$tmp"

# Dodaj źródło repozytorium. Wybierz komponent:
#   main     codzienne kompilacje rozwojowe
#   release  oficjalne wydania projektu macierzystego (26.05 i nowsze)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Obowiązkowo przed pierwszym uruchomieniem: skonfiguruj stację, radio i audio.
# Plik z pakietu jest tylko szablonem i musi zostać dostosowany do twojej konfiguracji.
sudo editor /etc/svxlink/svxlink.conf

# Włącz SvxLink przy starcie systemu i uruchom go teraz.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Sprawdź stan usługi i śledź jej dziennik.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Opcjonalny graficzny klient EchoLink (wymaga środowiska graficznego):
# sudo apt install qtel

Wymagane: Nie uruchamiaj usługi przed edycją pliku /etc/svxlink/svxlink.conf. Skonfiguruj co najmniej identyfikację stacji, logikę, odbiornik/nadajnik oraz ustawienia audio/PTT dla swojego sprzętu. Usługa odczytuje tę ścieżkę poprzez /etc/default/svxlink.

Jeśli apt update zgłasza błąd 404 dla tego źródła, pakiety dla nazwy kodowej twojego systemu nie są jeszcze budowane (zobacz tabelę poniżej) — zmień wtedy nazwę kodową w /etc/apt/sources.list.d/svxlink-db9cr.list na jedną z obsługiwanych. Następnie zwykłe sudo apt upgrade automatycznie pobiera nowe kompilacje codzienne (main) lub nowe wydania projektu macierzystego (release).

Nie włączaj obu komponentów jednocześnie, chyba że chcesz kompilacje codzienne: zawsze mają one wyższą wersję, więc apt zainstalowałby je zamiast wydań. Aby przełączyć istniejącą instalację z main na release, zmień komponent w /etc/apt/sources.list.d/svxlink-db9cr.list, uruchom sudo apt update, a następnie jawnie zainstaluj wersję wydania (jest to obniżenie wersji), np. sudo apt install svxlink=26.05.2-2~deb13. Pamiętaj, że w pakietach release (niezmieniony kod źródłowy projektu macierzystego) skrypty TCL w /usr/share/svxlink nie są chronione jako pliki konfiguracyjne; zmiany lokalne przechowuj w events.d/local/.

Stosowanie zmian konfiguracji

Po edycji /etc/svxlink/svxlink.conf (lub dowolnego pliku modułu /etc/svxlink/svxlink.d/*.conf) na działającej stacji przeładuj konfigurację bez przerywania aktywnej sesji:

sudo systemctl reload svxlink.service

Wysyła to sygnał SIGHUP, po którym SvxLink ponownie wczytuje swoją konfigurację. Użyj zamiast tego sudo systemctl restart svxlink.service, jeśli przeładowanie nie uwzględnia zmiany (niektóre ustawienia, np. to, które rdzenie logiki lub urządzenia dźwiękowe są ładowane, mogą wymagać pełnego restartu).

Instalacja starszej wersji

Ostatnie wersje pozostają dostępne w puli przez pewien czas po zastąpieniu przez nowsze (codzienne przez tydzień, cotygodniowe przez miesiąc, comiesięczne przez rok — zobacz sekcję „Retention” (przechowywanie) w UPSTREAM-SYNC.MD), dzięki czemu wadliwą kompilację codzienną zwykle można wycofać. Pakiety wydań projektu macierzystego (komponent release) nigdy nie są usuwane:

apt list -a svxlink   # lub qtel; wyświetla wszystkie wersje, które są jeszcze w repozytorium
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~deb13
sudo apt-mark hold svxlink   # opcjonalnie: zapobiega ponownej aktualizacji przez "apt upgrade"
# sudo apt-mark unhold svxlink   # później, aby wznowić automatyczne aktualizacje

Pakiety

PakietZawartość
svxlinkKomponenty serwerowe (svxlink, remotetrx, svxreflector, rdzenie logiki, skrypty zdarzeń Tcl). Zbudowany z: obsługą RTL-SDR przez bezpośrednie USB (dołączony fork librtlsdr/rtl_tcp od RTL-SDR Blog dla aktualnych odbiorników V3/V4; koliduje z dystrybucyjnymi librtlsdr0/rtl-sdr), dodatkowym rdzeniem logiki SipLogic (dołączony PJSIP/pjproject, linkowany statycznie), GPIO przez libgpiod oraz obsługą kodeków audio i wtyczek Speex/Opus/LADSPA. Instaluje usługę systemd. Nie zawiera Qtel ani pakietów dźwiękowych. Zawiera regułę udev, która daje usłudze SvxLink i użytkownikom zalogowanym do pulpitu dostęp do donglów USB RTL-SDR.
qtelGraficzny klient EchoLink (Qt6). Wymaga środowiska graficznego oraz pakietu svxlink w dokładnie tej samej wersji (współdzieli jego biblioteki echolib/async).

Systemy 32-bitowe: pakiety armhf są budowane dla Raspbiana (ARMv6+VFP), podstawy 32-bitowego Raspberry Pi OS, dzięki czemu działają na każdym modelu Raspberry Pi, w tym Pi 1, Zero i Zero W, a także instalują się na Debianie armhf (oba warianty są testowane). i386 (32-bitowe komputery PC) jest budowane wyłącznie dla Debiana 12: Debian 13 nie obsługuje już instalacji systemów i386. Pakiety 32-bitowe mają te same funkcje co 64-bitowe.

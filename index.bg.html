APT хранилище на SvxLink DB9CR

⚠ Тази страница е преведена автоматично с изкуствен интелект и може да съдържа грешки. Меродавна е английската версия. (English)

Пакети на svxlink-db9cr за Raspberry Pi OS и Debian в два компонента — изберете един:

  • main: ежедневни компилации за разработка от най-новия изходен код на този форк, а не стабилни версии.
  • release: официалните upstream версии на SvxLink (26.05 и по-нови), компилирани от непроменения изходен код на upstream версията със същите настройки за компилация и функции като ежедневните пакети. Всяка версия се запазва; apt upgrade преминава към всяка нова upstream версия.

Подробности ще намерите в хранилището с изходния код.

Upstream и локални промени

Това е ежедневно синхронизиран форк на sm0svx/svxlink, оригиналния проект SvxLink, с локално пакетиране и добавени функции върху него (RTL-SDR, SipLogic, отделният пакет qtel, това APT хранилище и други — пълния списък вижте в CHANGELOG.MD). За да видите точно какво се различава от upstream във всеки един момент, без да разчитате на моментна снимка тук, която може да остарее, сравнете актуалното състояние в GitHub: upstream master … master на този форк.

Бърз старт

Изпълнете на целевата система (правилните кодово име и архитектура се откриват автоматично):

# Импортиране на публичния ключ за подписване
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/svxlink-db9cr.gpg

# Добавяне на източника на хранилището. Изберете компонент:
#   main     ежедневни компилации за разработка
#   release  официални upstream версии (26.05 и по-нови)
component=main
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Задължително преди първото стартиране: конфигурирайте станцията, радиото и аудиото.
# Файлът от пакета е само шаблон и трябва да бъде адаптиран към вашата конфигурация.
sudo editor /etc/svxlink/svxlink.conf

# Активиране на SvxLink при зареждане на системата и стартиране веднага.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Проверка на състоянието на услугата и следене на нейния журнал.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Незадължителен графичен клиент за EchoLink (изисква графична работна среда):
# sudo apt install qtel

Задължително: Не стартирайте услугата, преди да редактирате /etc/svxlink/svxlink.conf. Конфигурирайте най-малко идентификацията на станцията, логиката, приемника/предавателя и настройките за аудио/PTT за вашия хардуер. Услугата получава този път чрез /etc/default/svxlink.

Ако apt update съобщи за грешка 404 за този източник, за кодовото име на вашата система все още няма компилации (вижте таблицата по-долу) — вместо това променете кодовото име в /etc/apt/sources.list.d/svxlink-db9cr.list на някое от поддържаните. След това обикновената команда sudo apt upgrade автоматично получава новите ежедневни компилации (main) или новите upstream версии (release).

Не активирайте двата компонента едновременно, освен ако не искате ежедневните компилации: те винаги имат по-висока версия, така че apt би ги инсталирал вместо официалните версии. За да превключите съществуваща инсталация от main към release, променете компонента в /etc/apt/sources.list.d/svxlink-db9cr.list, изпълнете sudo apt update и след това инсталирайте изрично версията от release (това е понижаване на версията), например sudo apt install svxlink=26.05.2-1~trixie. Имайте предвид, че в пакетите от release (непроменен upstream изходен код) TCL скриптовете в /usr/share/svxlink не са защитени като конфигурационни файлове; съхранявайте локалните промени в events.d/local/.

Прилагане на промени в конфигурацията

След редактиране на /etc/svxlink/svxlink.conf (или на който и да е модулен файл /etc/svxlink/svxlink.d/*.conf) на работеща станция презаредете конфигурацията, без да прекъсвате активна сесия:

sudo systemctl reload svxlink.service

Това изпраща SIGHUP, при който SvxLink прочита наново конфигурацията си. Използвайте вместо това sudo systemctl restart svxlink.service, ако презареждането не изглежда да прилага дадена промяна (някои настройки, например кои логически ядра или звукови устройства се зареждат, може да изискват пълно рестартиране).

Инсталиране на по-стара версия

Последните версии остават достъпни в pool още известно време, след като бъдат заменени от по-нови (ежедневните за една седмица, седмичните за един месец, месечните за една година — вижте раздела „Retention“ (съхранение) в UPSTREAM-SYNC.MD), така че неуспешна ежедневна компилация обикновено може да бъде върната назад. Пакетите с upstream версии (компонент release) никога не се премахват:

apt list -a svxlink   # или qtel; показва всички версии, които все още са в хранилището
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~trixie
sudo apt-mark hold svxlink   # по избор: спира повторното обновяване от "apt upgrade"
# sudo apt-mark unhold svxlink   # по-късно, за възобновяване на автоматичните обновления

Пакети

ПакетСъдържание
svxlinkСървърни компоненти (svxlink, remotetrx, svxreflector, логически ядра, Tcl скриптове за събития). Компилиран с: поддръжка на RTL-SDR чрез директна USB връзка (включен форк на librtlsdr/rtl_tcp от RTL-SDR Blog за текущите донгъли V3/V4; в конфликт с пакетите librtlsdr0/rtl-sdr на дистрибуцията), предоставеното от общността логическо ядро SipLogic (включен PJSIP/pjproject, статично свързан), GPIO чрез libgpiod и поддръжка на аудиокодеци и плъгини Speex/Opus/LADSPA. Инсталира systemd услуга. Не включва Qtel и звукови пакети.
qtelГрафичен клиент за EchoLink (Qt6). Изисква графична работна среда и пакета svxlink с абсолютно същата версия (споделя неговите библиотеки echolib/async).

32-битови системи: пакетите armhf се компилират за Raspbian (ARMv6+VFP), основата на 32-битовата Raspberry Pi OS, така че работят на всеки модел Raspberry Pi, включително Pi 1, Zero и Zero W, а също се инсталират и на Debian armhf (и двете са тествани). i386 (32-битови персонални компютри) се компилира само за Debian 12: Debian 13 вече не поддържа инсталиране на i386 системи. 32-битовите пакети съдържат същите функции като 64-битовите.

Ключ за подписване

pubkey.gpg — импортира се автоматично от командите за бърз старт по-горе.

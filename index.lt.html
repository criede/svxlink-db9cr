SvxLink DB9CR APT saugykla

⚠ Šis puslapis išverstas automatiškai naudojant dirbtinį intelektą ir gali turėti klaidų. Galiojanti yra angliška versija. (English)

Projekto svxlink-db9cr paketai, skirti Raspberry Pi OS ir Debian, dviejuose komponentuose — pasirinkite vieną:

  • main: kasdieniai kūrimo versijų rinkiniai iš naujausio šios atšakos išeitinio kodo, o ne stabilios laidos.
  • release: oficialios pirminio (upstream) SvxLink projekto laidos (26.05 ir naujesnės), sukompiliuotos iš nepakeisto pirminės laidos išeitinio kodo su tais pačiais kompiliavimo nustatymais ir funkcijomis kaip kasdieniai paketai. Saugomos visos laidos; apt upgrade pereina prie kiekvienos naujos pirminės laidos.

Daugiau informacijos rasite išeitinio kodo saugykloje.

Pirminis projektas ir vietiniai pakeitimai

Tai kasdien sinchronizuojama atšaka projekto sm0svx/svxlink, kuris yra originalus SvxLink projektas, su papildomai pridėtu vietiniu pakavimu ir funkcijomis (RTL-SDR, SipLogic, atskiras qtel paketas, ši APT saugykla ir kita — visą sąrašą rasite faile CHANGELOG.MD). Norėdami bet kuriuo metu tiksliai pamatyti, kuo ji skiriasi nuo pirminio projekto, nepasikliaudami čia pateikta ir pasenti galinčia momentine kopija, palyginkite tiesiogiai GitHub: pirminio projekto master … šios atšakos master.

Greita pradžia

Vykdykite tikslinėje sistemoje (tinkamas kodinis pavadinimas / architektūra nustatomi automatiškai):

# Importuokite viešąjį pasirašymo raktą
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/svxlink-db9cr.gpg

# Pridėkite saugyklos šaltinį. Pasirinkite komponentą:
#   main     kasdieniai kūrimo versijų rinkiniai
#   release  oficialios pirminio projekto laidos (26.05 ir naujesnės)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Privaloma prieš pirmąjį paleidimą: sukonfigūruokite savo stotį, radijo stotį ir garsą.
# Pakete pateiktas failas yra tik šablonas, jį būtina pritaikyti savo įrangai.
sudo editor /etc/svxlink/svxlink.conf

# Įjunkite SvxLink paleidimą įkrovos metu ir paleiskite jį dabar.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Patikrinkite tarnybos būseną ir stebėkite jos žurnalą.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Pasirenkamas grafinis EchoLink klientas (reikia darbalaukio aplinkos):
# sudo apt install qtel

Būtina: Nepaleiskite tarnybos, kol nepakeitėte failo /etc/svxlink/svxlink.conf. Sukonfigūruokite bent stoties identifikaciją, logiką, imtuvą/siųstuvą ir garso/PTT nustatymus pagal savo aparatinę įrangą. Tarnyba šį kelią nuskaito per /etc/default/svxlink.

Jei apt update šiam šaltiniui praneša klaidą 404, jūsų sistemos kodiniam pavadinimui paketai dar nekompiliuojami (žr. lentelę žemiau) — vietoj to faile /etc/apt/sources.list.d/svxlink-db9cr.list pakeiskite kodinį pavadinimą į vieną iš palaikomų. Vėliau įprastas sudo apt upgrade automatiškai įdiegs naujus kasdienius rinkinius (main) arba naujas pirminio projekto laidas (release).

Neįjunkite abiejų komponentų vienu metu, nebent norite kasdienių rinkinių: jų versija visada aukštesnė, todėl apt juos įdiegtų vietoj laidų. Norėdami esamą įdiegtį perjungti iš main į release, pakeiskite komponentą faile /etc/apt/sources.list.d/svxlink-db9cr.list, paleiskite sudo apt update, tada aiškiai nurodę įdiekite laidos versiją (tai yra versijos pažeminimas), pvz., sudo apt install svxlink=26.05.2-1~trixie. Atkreipkite dėmesį, kad release paketuose (nepakeistas pirminio projekto išeitinis kodas) TCL scenarijai kataloge /usr/share/svxlink nėra apsaugoti kaip konfigūracijos failai; vietinius pakeitimus laikykite kataloge events.d/local/.

Konfigūracijos pakeitimų pritaikymas

Pakeitę failą /etc/svxlink/svxlink.conf (arba bet kurį /etc/svxlink/svxlink.d/*.conf modulio failą) veikiančioje stotyje, iš naujo įkelkite jį nenutraukdami aktyvaus seanso:

sudo systemctl reload svxlink.service

Tai išsiunčia signalą SIGHUP, kurį gavęs SvxLink iš naujo nuskaito savo konfigūraciją. Jei atrodo, kad pakartotinis įkėlimas pakeitimo nepritaikė, vietoj to naudokite sudo systemctl restart svxlink.service (kai kuriems nustatymams, pvz., kurie logikos branduoliai ar garso įrenginiai įkeliami, gali reikėti visiško paleidimo iš naujo).

Senesnės versijos diegimas

Naujausios versijos, jas pakeitus naujesnėmis, dar kurį laiką lieka prieinamos pool kataloge (kasdienės — savaitę, savaitinės — mėnesį, mėnesinės — metus; žr. skyrių "Retention" (saugojimas) faile UPSTREAM-SYNC.MD), todėl nepavykusį kasdienį rinkinį paprastai galima atšaukti. Pirminio projekto laidų paketai (release komponentas) niekada nešalinami:

apt list -a svxlink   # arba qtel; išvardija visas saugykloje dar esančias versijas
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~trixie
sudo apt-mark hold svxlink   # neprivaloma: neleidžia "apt upgrade" vėl jos atnaujinti
# sudo apt-mark unhold svxlink   # vėliau, norint vėl įjungti automatinius naujinimus

Paketai

PaketasTurinys
svxlinkServerio komponentai (svxlink, remotetrx, svxreflector, logikos branduoliai, Tcl įvykių scenarijai). Sukompiliuota su: RTL-SDR tiesioginio USB palaikymu (pridėta RTL-SDR Blog librtlsdr/rtl_tcp atšaka dabartiniams V3/V4 imtuvams; konfliktuoja su distribucijos librtlsdr0/rtl-sdr), bendruomenės sukurtu SipLogic logikos branduoliu (pridėtas PJSIP/pjproject, susietas statiškai), GPIO per libgpiod ir Speex/Opus/LADSPA garso kodekų bei įskiepių palaikymu. Įdiegia systemd tarnybą. Neapima Qtel ir garsų paketų.
qtelGrafinis EchoLink klientas (Qt6). Reikia darbalaukio aplinkos ir lygiai tos pačios versijos svxlink paketo (naudoja jo echolib/async bibliotekas).

32 bitų sistemos: armhf paketai kompiliuojami Raspbian (ARMv6+VFP) pagrindu, kuris yra 32 bitų Raspberry Pi OS pagrindas, todėl jie veikia visuose Raspberry Pi modeliuose, įskaitant Pi 1, Zero ir Zero W, ir taip pat diegiami Debian armhf (abu variantai išbandyti). i386 (32 bitų asmeniniai kompiuteriai) kompiliuojami tik Debian 12: Debian 13 nebepalaiko i386 sistemų diegimo. 32 bitų paketuose yra tos pačios funkcijos kaip ir 64 bitų.

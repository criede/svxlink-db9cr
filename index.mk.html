APT репозиториум на SvxLink DB9CR

⚠ Оваа страница е автоматски преведена со вештачка интелигенција и може да содржи грешки. Меродавна е англиската верзија. (English)

Пакети на svxlink-db9cr за Raspberry Pi OS и Debian, во две компоненти — изберете една:

  • main: дневни развојни верзии од најновиот изворен код на овој форк, а не стабилни изданија.
  • release: официјалните upstream изданија на SvxLink (26.05 и понови), изградени од непроменетиот изворен код на upstream изданието со истите поставки за градење и функции како дневните пакети. Секое издание се чува; apt upgrade преминува на секое ново upstream издание.

Деталите ќе ги најдете во репозиториумот со изворниот код.

Upstream и локални промени

Ова е секојдневно синхронизиран форк на sm0svx/svxlink, оригиналниот проект SvxLink, со локално пакување и додадени функции врз него (RTL-SDR, SipLogic, посебниот пакет qtel, овој APT репозиториум и друго — целосниот список видете го во CHANGELOG.MD). За во секој момент точно да видите што се разликува од upstream, без да се потпирате на снимка овде што може да застари, споредете ја моменталната состојба на GitHub: upstream master … master на овој форк.

Брз почеток

Извршете на целниот систем (соодветното кодно име и архитектура се откриваат автоматски):

# Увоз на јавниот клуч за потпишување
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/svxlink-db9cr.gpg

# Додавање на изворот на репозиториумот. Изберете компонента:
#   main     дневни развојни верзии
#   release  официјални upstream изданија (26.05 и понови)
component=main
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Задолжително пред првото стартување: конфигурирајте ја станицата, радиото и аудиото.
# Датотеката од пакетот е само шаблон и мора да се прилагоди на вашата поставеност.
sudo editor /etc/svxlink/svxlink.conf

# Овозможување на SvxLink при подигање на системот и стартување веднаш.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Проверка на состојбата на сервисот и следење на неговиот дневник.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Опционален графички EchoLink клиент (бара графичка работна околина):
# sudo apt install qtel

Задолжително: Не стартувајте го сервисот пред да ја уредите /etc/svxlink/svxlink.conf. Конфигурирајте барем идентитетот на станицата, логиката, приемникот/предавателот и поставките за аудио/PTT за вашиот хардвер. Сервисот ја чита оваа патека преку /etc/default/svxlink.

Ако apt update пријави грешка 404 за овој извор, за кодното име на вашиот систем сè уште нема изградени пакети (видете ја табелата подолу) — наместо тоа, во /etc/apt/sources.list.d/svxlink-db9cr.list сменете го кодното име во некое од поддржаните. Потоа, вообичаеното sudo apt upgrade автоматски ги презема новите дневни верзии (main) или новите upstream изданија (release).

Не овозможувајте ги двете компоненти истовремено, освен ако не ги сакате дневните верзии: тие секогаш имаат повисока верзија, па apt би ги инсталирал наместо изданијата. За да префрлите постоечка инсталација од main на release, сменете ја компонентата во /etc/apt/sources.list.d/svxlink-db9cr.list, извршете sudo apt update, а потоа експлицитно инсталирајте ја верзијата на изданието (тоа е враќање на постара верзија), на пр. sudo apt install svxlink=26.05.2-1~trixie. Имајте предвид дека во пакетите release (непроменет upstream изворен код) TCL скриптите во /usr/share/svxlink не се заштитени како конфигурациски датотеки; чувајте ги локалните промени во events.d/local/.

Примена на промени во конфигурацијата

По уредувањето на /etc/svxlink/svxlink.conf (или која било модулска датотека /etc/svxlink/svxlink.d/*.conf) на станица што работи, повторно вчитајте ја конфигурацијата без прекинување на активна сесија:

sudo systemctl reload svxlink.service

Ова испраќа SIGHUP, при кој SvxLink повторно ја вчитува својата конфигурација. Наместо тоа, користете sudo systemctl restart svxlink.service ако повторното вчитување не ја применува некоја промена (некои поставки, на пример кои логички јадра или звучни уреди се вчитуваат, може да бараат целосно рестартирање).

Инсталирање постара верзија

Неодамнешните верзии остануваат достапни во pool уште некое време откако ќе бидат заменети со понови (дневните една недела, неделните еден месец, месечните една година — видете го делот „Retention“ (задржување) во UPSTREAM-SYNC.MD), така што лоша дневна верзија обично може да се врати. Пакетите со upstream изданија (компонента release) никогаш не се отстрануваат:

apt list -a svxlink   # или qtel; ги прикажува сите верзии што сè уште се во репозиториумот
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~trixie
sudo apt-mark hold svxlink   # опционално: спречува "apt upgrade" повторно да ја надгради
# sudo apt-mark unhold svxlink   # подоцна, за продолжување на автоматските ажурирања

Пакети

ПакетСодржи
svxlinkСерверски компоненти (svxlink, remotetrx, svxreflector, логички јадра, Tcl скрипти за настани). Изграден со: поддршка за RTL-SDR преку директна USB врска (вклучен RTL-SDR Blog форк на librtlsdr/rtl_tcp за актуелните V3/V4 донгли; во конфликт со пакетите librtlsdr0/rtl-sdr од дистрибуцијата), логичкото јадро SipLogic придонесено од заедницата (вклучен PJSIP/pjproject, статички поврзан), GPIO преку libgpiod и поддршка за аудиокодеци и приклучоци Speex/Opus/LADSPA. Инсталира systemd сервис. Не ги вклучува Qtel и звучните пакети.
qtelГрафички EchoLink клиент (Qt6). Бара графичка работна околина и пакетот svxlink со точно истата верзија (ги споделува неговите библиотеки echolib/async).

32-битни системи: пакетите armhf се градат за Raspbian (ARMv6+VFP), основата на 32-битниот Raspberry Pi OS, така што работат на секој модел Raspberry Pi, вклучувајќи ги Pi 1, Zero и Zero W, а се инсталираат и на Debian armhf (двете се тестирани). i386 (32-битни компјутери) се гради само за Debian 12: Debian 13 повеќе не поддржува инсталирање i386 системи. 32-битните пакети ги содржат истите функции како 64-битните.

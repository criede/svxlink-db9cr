Depozitul APT SvxLink DB9CR

⚠ Această pagină a fost tradusă automat cu ajutorul inteligenței artificiale și poate conține erori. Versiunea în limba engleză este cea de referință. (English)

Pachete svxlink-db9cr pentru Raspberry Pi OS și Debian, în două componente — alege una:

  • main: build-uri zilnice de dezvoltare din cea mai recentă sursă a acestui fork, nu versiuni stabile.
  • release: versiunile oficiale upstream ale SvxLink (26.05 și mai noi), compilate din sursa nemodificată a versiunilor upstream, cu aceleași setări de compilare și aceleași funcționalități ca pachetele zilnice. Fiecare versiune este păstrată; apt upgrade trece la fiecare nouă versiune upstream.

Consultă depozitul de cod sursă pentru detalii.

Upstream și modificări locale

Acesta este un fork sincronizat zilnic al sm0svx/svxlink, proiectul SvxLink original, cu împachetare locală și funcționalități suplimentare adăugate deasupra (RTL-SDR, SipLogic, pachetul separat qtel, acest depozit APT și altele — consultă CHANGELOG.MD pentru lista completă). Pentru a vedea exact ce diferă față de upstream în orice moment, fără a te baza pe un instantaneu de aici care se poate învechi, compară în timp real pe GitHub: upstream master … master-ul acestui fork.

Pornire rapidă

Rulează pe sistemul țintă (detectează automat numele de cod și arhitectura corecte):

# Importă cheia publică de semnare
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/svxlink-db9cr.gpg

# Adaugă sursa depozitului. Alege componenta:
#   main     build-uri zilnice de dezvoltare
#   release  versiuni oficiale upstream (26.05 și mai noi)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Obligatoriu înainte de prima pornire: configurează stația, echipamentul radio și partea audio.
# Fișierul din pachet este doar un șablon și trebuie adaptat configurației tale.
sudo editor /etc/svxlink/svxlink.conf

# Activează SvxLink la pornirea sistemului și pornește-l acum.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Verifică starea serviciului și urmărește jurnalul acestuia.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Client EchoLink grafic opțional (necesită un mediu desktop):
# sudo apt install qtel

Obligatoriu: Nu porni serviciul înainte de a edita /etc/svxlink/svxlink.conf. Configurează cel puțin identitatea stației, logica, receptorul/emițătorul și setările audio/PTT pentru hardware-ul tău. Serviciul citește această cale prin /etc/default/svxlink.

Dacă apt update raportează o eroare 404 pentru această sursă, pentru numele de cod al sistemului tău nu se compilează încă pachete (consultă tabelul de mai jos) — în schimb, modifică numele de cod din /etc/apt/sources.list.d/svxlink-db9cr.list într-unul dintre cele suportate. Ulterior, un sudo apt upgrade obișnuit preia automat noile build-uri zilnice (main) sau noile versiuni upstream (release).

Nu activa ambele componente simultan decât dacă dorești build-urile zilnice: acestea au întotdeauna versiunea mai mare, așa că apt le-ar instala peste versiunile release. Pentru a trece o instalare existentă de la main la release, schimbă componenta în /etc/apt/sources.list.d/svxlink-db9cr.list, rulează sudo apt update, apoi instalează explicit versiunea release (este un downgrade, adică o trecere la o versiune mai veche), de ex. sudo apt install svxlink=26.05.2-1~trixie. Reține că în pachetele release (sursă upstream nemodificată) scripturile TCL din /usr/share/svxlink nu sunt protejate ca fișiere de configurare; păstrează modificările locale în events.d/local/.

Aplicarea modificărilor de configurare

După editarea /etc/svxlink/svxlink.conf (sau a oricărui fișier de modul /etc/svxlink/svxlink.d/*.conf) pe o stație în funcțiune, reîncarcă configurația fără a întrerupe o sesiune activă:

sudo systemctl reload svxlink.service

Aceasta trimite SIGHUP, la primirea căruia SvxLink își recitește configurația. Folosește în schimb sudo systemctl restart svxlink.service dacă o reîncărcare nu pare să preia o modificare (unele setări, cum ar fi ce nuclee logice sau ce dispozitive de sunet sunt încărcate, pot necesita o repornire completă).

Instalarea unei versiuni mai vechi

Versiunile recente rămân disponibile în pool o vreme după ce au fost înlocuite (zilnic timp de o săptămână, săptămânal timp de o lună, lunar timp de un an — consultă „Retention” (păstrare) în UPSTREAM-SYNC.MD), așa că un build zilnic defect poate fi de obicei anulat (rollback). Pachetele versiunilor upstream (componenta release) nu sunt eliminate niciodată:

apt list -a svxlink   # sau qtel; afișează toate versiunile aflate încă în depozit
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~trixie
sudo apt-mark hold svxlink   # opțional: împiedică "apt upgrade" să o actualizeze din nou
# sudo apt-mark unhold svxlink   # mai târziu, pentru a relua actualizările automate

Sisteme pe 32 de biți: pachetele armhf sunt compilate pentru Raspbian (ARMv6+VFP), baza Raspberry Pi OS pe 32 de biți, deci rulează pe orice model Raspberry Pi, inclusiv Pi 1, Zero și Zero W, și se instalează și pe Debian armhf (ambele sunt testate). i386 (PC-uri pe 32 de biți) este compilat doar pentru Debian 12: Debian 13 nu mai suportă instalarea sistemelor i386. Pachetele pe 32 de biți conțin aceleași funcționalități ca cele pe 64 de biți.

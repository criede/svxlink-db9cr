SvxLink DB9CR APT-förråd

⚠ Den här sidan har översatts automatiskt med artificiell intelligens och kan innehålla fel. Den engelska versionen gäller. (English)

Paket av svxlink-db9cr för Raspberry Pi OS och Debian, i två komponenter — välj en:

  • main: dagliga utvecklingsbyggen från den senaste källkoden i denna fork, inte stabila utgåvor.
  • release: de officiella upstream-utgåvorna av SvxLink (26.05 och nyare), byggda från den oförändrade upstream-källkoden för utgåvan med samma bygginställningar och funktioner som de dagliga paketen. Varje utgåva behålls; apt upgrade går över till varje ny upstream-utgåva.

Se källkodsförrådet för detaljer.

Upstream och lokala ändringar

Detta är en dagligen synkroniserad fork av sm0svx/svxlink, det ursprungliga SvxLink-projektet, med lokal paketering och ytterligare funktioner ovanpå (RTL-SDR, SipLogic, det separata paketet qtel, detta APT-förråd med mera — se CHANGELOG.MD för den fullständiga listan). För att när som helst se exakt vad som skiljer sig från upstream, utan att förlita dig på en ögonblicksbild här som blir inaktuell, kan du jämföra live på GitHub: upstream master … denna forks master.

Snabbstart

Kör på målsystemet (identifierar automatiskt rätt kodnamn/arkitektur):

# Importera den publika signeringsnyckeln
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/svxlink-db9cr.gpg

# Lägg till förrådskällan. Välj komponent:
#   main     dagliga utvecklingsbyggen
#   release  officiella upstream-utgåvor (26.05 och nyare)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Obligatoriskt före första start: konfigurera din station, radio och ljud.
# Den medföljande filen är bara en mall och måste anpassas till din uppsättning.
sudo editor /etc/svxlink/svxlink.conf

# Aktivera SvxLink vid uppstart och starta den nu.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Kontrollera tjänstens status och följ dess logg.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Valfri grafisk EchoLink-klient (kräver en skrivbordsmiljö):
# sudo apt install qtel

Krävs: Starta inte tjänsten innan du har redigerat /etc/svxlink/svxlink.conf. Konfigurera åtminstone stationens identitet, logik, mottagare/sändare samt ljud-/PTT-inställningar för din hårdvara. Tjänsten läser denna sökväg via /etc/default/svxlink.

Om apt update rapporterar 404 för den här källan byggs ditt systems kodnamn ännu inte (se tabellen nedan) — ändra i stället kodnamnet i /etc/apt/sources.list.d/svxlink-db9cr.list till ett av de som stöds. Därefter hämtar en vanlig sudo apt upgrade automatiskt nya dagliga byggen (main) eller nya upstream-utgåvor (release).

Aktivera inte båda komponenterna samtidigt om du inte vill ha de dagliga byggena: de har alltid den högre versionen, så apt skulle installera dem i stället för utgåvorna. För att byta en befintlig installation från main till release, ändra komponenten i /etc/apt/sources.list.d/svxlink-db9cr.list, kör sudo apt update och installera sedan utgåveversionen uttryckligen (det är en nedgradering), t.ex. sudo apt install svxlink=26.05.2-1~trixie. Observera att i release-paket (oförändrad upstream-källkod) är TCL-skripten under /usr/share/svxlink inte skyddade som konfigurationsfiler; lägg lokala ändringar i events.d/local/.

Tillämpa konfigurationsändringar

Efter att ha redigerat /etc/svxlink/svxlink.conf (eller någon modulfil /etc/svxlink/svxlink.d/*.conf) på en station som är igång läser du in den på nytt utan att avbryta en aktiv session:

sudo systemctl reload svxlink.service

Detta skickar SIGHUP, varvid SvxLink läser in sin konfiguration på nytt. Använd i stället sudo systemctl restart svxlink.service om en omladdning inte verkar få med en ändring (vissa inställningar, till exempel vilka logikkärnor eller ljudenheter som läses in, kan kräva en fullständig omstart).

Installera en äldre version

Nyliga versioner finns kvar i poolen en tid efter att de har ersatts (dagligen i en vecka, veckovis i en månad, månadsvis i ett år — se ”Retention” (lagringstid) i UPSTREAM-SYNC.MD), så ett dåligt dagligt bygge kan oftast rullas tillbaka. Paket med upstream-utgåvor (komponenten release) tas aldrig bort:

apt list -a svxlink   # eller qtel; listar alla versioner som fortfarande finns i förrådet
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~trixie
sudo apt-mark hold svxlink   # valfritt: hindrar "apt upgrade" från att uppgradera den igen
# sudo apt-mark unhold svxlink   # senare, för att återuppta automatiska uppdateringar

Paket

PaketInnehåll
svxlinkServerkomponenter (svxlink, remotetrx, svxreflector, logikkärnor, Tcl-händelseskript). Byggt med: RTL-SDR-stöd via direkt USB (medföljande RTL-SDR Blog-fork av librtlsdr/rtl_tcp för aktuella V3/V4-donglar; står i konflikt med distributionens librtlsdr0/rtl-sdr), den bidragna SipLogic-logikkärnan (medföljande PJSIP/pjproject, statiskt länkat), GPIO via libgpiod samt stöd för ljudkodekarna och insticksprogrammen Speex/Opus/LADSPA. Installerar en systemd-tjänst. Innehåller inte Qtel eller ljudpaket.
qtelGrafisk EchoLink-klient (Qt6). Kräver en skrivbordsmiljö och paketet svxlink i exakt samma version (delar dess echolib/async-bibliotek).

32-bitarssystem: armhf-paket byggs mot Raspbian (ARMv6+VFP), grunden för 32-bitars Raspberry Pi OS, så de körs på alla Raspberry Pi-modeller inklusive Pi 1, Zero och Zero W, och kan även installeras på Debian armhf (båda är testade). i386 (32-bitars pc) byggs endast för Debian 12: Debian 13 stöder inte längre installation av i386-system. 32-bitarspaketen har samma funktioner som 64-bitarspaketen.

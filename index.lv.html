SvxLink DB9CR APT repozitorijs

⚠ Šī lapa ir automātiski tulkota ar mākslīgā intelekta palīdzību un var saturēt kļūdas. Noteicošā ir angļu valodas versija. (English)

Projekta svxlink-db9cr pakotnes Raspberry Pi OS un Debian sistēmām divos komponentos — izvēlieties vienu:

  • main: ikdienas izstrādes būvējumi no šī atzarojuma (fork) jaunākā pirmkoda, nevis stabilie laidieni.
  • release: oficiālie sākotnējā (upstream) SvxLink projekta laidieni (26.05 un jaunāki), būvēti no nemainīta sākotnējā laidiena pirmkoda ar tiem pašiem būvēšanas iestatījumiem un funkcijām kā ikdienas pakotnes. Visi laidieni tiek saglabāti; apt upgrade pāriet uz katru jaunu sākotnējā projekta laidienu.

Sīkāka informācija ir pirmkoda repozitorijā.

Sākotnējais projekts un vietējās izmaiņas

Šis ir katru dienu sinhronizēts atzarojums no sm0svx/svxlink, kas ir oriģinālais SvxLink projekts, ar papildus pievienotu vietējo pakošanu un funkcijām (RTL-SDR, SipLogic, atsevišķā qtel pakotne, šis APT repozitorijs un citas — pilns saraksts ir failā CHANGELOG.MD). Lai jebkurā brīdī precīzi redzētu, kas atšķiras no sākotnējā projekta, nepaļaujoties uz šeit esošu momentuzņēmumu, kas var novecot, salīdziniet tiešsaistē GitHub: sākotnējā projekta master … šī atzarojuma master.

Ātrā sākšana

Izpildiet mērķa sistēmā (pareizais koda nosaukums/arhitektūra tiek noteikti automātiski):

# Importējiet publisko parakstīšanas atslēgu
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/svxlink-db9cr.gpg

# Pievienojiet repozitorija avotu. Izvēlieties komponentu:
#   main     ikdienas izstrādes būvējumi
#   release  oficiālie sākotnējā projekta laidieni (26.05 un jaunāki)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Obligāti pirms pirmās palaišanas: konfigurējiet savu staciju, radio un audio.
# Pakotnē iekļautais fails ir tikai veidne, un tas jāpielāgo jūsu iekārtai.
sudo editor /etc/svxlink/svxlink.conf

# Iespējojiet SvxLink palaišanu sāknēšanas laikā un palaidiet to tūlīt.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Pārbaudiet servisa stāvokli un sekojiet tā žurnālam.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Neobligāts grafisks EchoLink klients (nepieciešama darbvirsmas vide):
# sudo apt install qtel

Obligāti: Nepalaidiet servisu, pirms neesat rediģējuši failu /etc/svxlink/svxlink.conf. Konfigurējiet vismaz stacijas identitāti, loģiku, uztvērēju/raidītāju un audio/PTT iestatījumus atbilstoši savai aparatūrai. Serviss nolasa šo ceļu ar /etc/default/svxlink starpniecību.

Ja apt update šim avotam ziņo par kļūdu 404, jūsu sistēmas koda nosaukumam pakotnes vēl netiek būvētas (skatiet tabulu zemāk) — tā vietā failā /etc/apt/sources.list.d/svxlink-db9cr.list nomainiet koda nosaukumu uz kādu no atbalstītajiem. Pēc tam parasta sudo apt upgrade automātiski iegūst jaunus ikdienas būvējumus (main) vai jaunus sākotnējā projekta laidienus (release).

Neiespējojiet abus komponentus vienlaikus, ja vien nevēlaties ikdienas būvējumus: tiem vienmēr ir augstāka versija, tāpēc apt tos instalētu laidienu vietā. Lai esošu instalāciju pārslēgtu no main uz release, nomainiet komponentu failā /etc/apt/sources.list.d/svxlink-db9cr.list, izpildiet sudo apt update un pēc tam skaidri norādot instalējiet laidiena versiju (tā ir versijas pazemināšana), piem., sudo apt install svxlink=26.05.2-1~trixie. Ņemiet vērā, ka release pakotnēs (nemainīts sākotnējā projekta pirmkods) TCL skripti direktorijā /usr/share/svxlink nav aizsargāti kā konfigurācijas faili; vietējās izmaiņas glabājiet direktorijā events.d/local/.

Konfigurācijas izmaiņu piemērošana

Pēc faila /etc/svxlink/svxlink.conf (vai jebkura /etc/svxlink/svxlink.d/*.conf moduļa faila) rediģēšanas strādājošā stacijā pārlādējiet to, nepārtraucot aktīvo sesiju:

sudo systemctl reload svxlink.service

Tas nosūta signālu SIGHUP, pēc kura SvxLink atkārtoti nolasa savu konfigurāciju. Ja šķiet, ka pārlāde izmaiņas nepiemēro, tā vietā izmantojiet sudo systemctl restart svxlink.service (dažiem iestatījumiem, piemēram, kuri loģikas kodoli vai skaņas ierīces tiek ielādēti, var būt nepieciešama pilnīga restartēšana).

Vecākas versijas instalēšana

Nesenās versijas pēc aizstāšanas ar jaunākām vēl kādu laiku paliek pieejamas pool direktorijā (ikdienas — nedēļu, iknedēļas — mēnesi, ikmēneša — gadu; skatiet sadaļu "Retention" (saglabāšana) failā UPSTREAM-SYNC.MD), tāpēc sliktu ikdienas būvējumu parasti var atritināt atpakaļ. Sākotnējā projekta laidienu pakotnes (release komponents) nekad netiek dzēstas:

apt list -a svxlink   # vai qtel; uzskaita visas versijas, kas vēl ir repozitorijā
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~trixie
sudo apt-mark hold svxlink   # neobligāti: neļauj "apt upgrade" to atkal atjaunināt
# sudo apt-mark unhold svxlink   # vēlāk, lai atsāktu automātiskos atjauninājumus

Pakotnes

PakotneSaturs
svxlinkServera komponenti (svxlink, remotetrx, svxreflector, loģikas kodoli, Tcl notikumu skripti). Būvēts ar: RTL-SDR tiešā USB atbalstu (iekļauts RTL-SDR Blog librtlsdr/rtl_tcp atzarojums pašreizējiem V3/V4 uztvērējiem; konfliktē ar distribūcijas librtlsdr0/rtl-sdr), kopienas izstrādāto SipLogic loģikas kodolu (iekļauts PJSIP/pjproject, statiski saistīts), GPIO ar libgpiod un Speex/Opus/LADSPA audio kodeku un spraudņu atbalstu. Instalē systemd servisu. Neietver Qtel un skaņu pakas.
qtelGrafisks EchoLink klients (Qt6). Nepieciešama darbvirsmas vide un tieši tādas pašas versijas svxlink pakotne (izmanto tās echolib/async bibliotēkas).

32 bitu sistēmas: armhf pakotnes tiek būvētas pret Raspbian (ARMv6+VFP), kas ir 32 bitu Raspberry Pi OS pamatā, tāpēc tās darbojas visos Raspberry Pi modeļos, ieskaitot Pi 1, Zero un Zero W, un tās var instalēt arī Debian armhf (abi varianti ir pārbaudīti). i386 (32 bitu datori) tiek būvēts tikai Debian 12: Debian 13 vairs neatbalsta i386 sistēmu instalēšanu. 32 bitu pakotnēm ir tās pašas funkcijas kā 64 bitu pakotnēm.

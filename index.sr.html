SvxLink DB9CR APT репозиторијум

⚠ Ова страница је аутоматски преведена помоћу вештачке интелигенције и може садржати грешке. Меродавна је енглеска верзија. (English)

Пакети svxlink-db9cr за Raspberry Pi OS и Debian, у две компоненте — изаберите једну:

  • main: дневне развојне верзије из најновијег изворног кода овог форка, а не стабилна издања.
  • release: званична upstream издања SvxLink-а (26.05 и новија), изграђена из неизмењеног изворног кода upstream издања са истим подешавањима изградње и функцијама као и дневни пакети. Свако издање се чува; apt upgrade прелази на свако ново upstream издање.

Детаље потражите у репозиторијуму изворног кода.

Upstream и локалне измене

Ово је свакодневно синхронизован форк пројекта sm0svx/svxlink, оригиналног пројекта SvxLink, са локалним паковањем и додатим функцијама поврх њега (RTL-SDR, SipLogic, засебан пакет qtel, овај APT репозиторијум и још много тога — потпуну листу погледајте у CHANGELOG.MD). Да бисте у било ком тренутку тачно видели шта се разликује у односу на upstream, без ослањања на снимак стања овде који може да застари, упоредите тренутно стање на GitHub-у: upstream master … master овог форка.

Брзи почетак

Покрените на циљном систему (одговарајуће кодно име и архитектура се откривају аутоматски):

# Увоз јавног кључа за потписивање
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/svxlink-db9cr.gpg

# Додавање извора репозиторијума. Изаберите компоненту:
#   main     дневне развојне верзије
#   release  званична upstream издања (26.05 и новија)
component=main
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Обавезно пре првог покретања: подесите станицу, радио-уређај и звук.
# Датотека из пакета је само шаблон и мора се прилагодити вашој конфигурацији.
sudo editor /etc/svxlink/svxlink.conf

# Омогућавање покретања SvxLink-а при подизању система и покретање одмах.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Провера стања сервиса и праћење његовог дневника.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Опциони графички EchoLink клијент (захтева графичко радно окружење):
# sudo apt install qtel

Обавезно: Не покрећите сервис пре уређивања датотеке /etc/svxlink/svxlink.conf. Подесите барем идентитет станице, логику, пријемник/предајник и подешавања звука/PTT-а за ваш хардвер. Сервис чита ову путању преко /etc/default/svxlink.

Ако apt update пријави грешку 404 за овај извор, за кодно име вашег система још нема изграђених пакета (погледајте табелу испод) — уместо тога, у датотеци /etc/apt/sources.list.d/svxlink-db9cr.list промените кодно име у неко од подржаних. Након тога, уобичајено sudo apt upgrade аутоматски преузима нове дневне верзије (main) или нова upstream издања (release).

Не омогућавајте обе компоненте истовремено, осим ако желите дневне верзије: оне увек имају вишу верзију, па би их apt инсталирао уместо издања. Да бисте постојећу инсталацију пребацили са main на release, промените компоненту у /etc/apt/sources.list.d/svxlink-db9cr.list, покрените sudo apt update, а затим изричито инсталирајте верзију издања (то је враћање на старију верзију), нпр. sudo apt install svxlink=26.05.2-1~trixie. Имајте у виду да у пакетима release (неизмењен upstream изворни код) TCL скрипте у /usr/share/svxlink нису заштићене као конфигурационе датотеке; локалне измене чувајте у events.d/local/.

Примена измена конфигурације

Након уређивања /etc/svxlink/svxlink.conf (или било које модулске датотеке /etc/svxlink/svxlink.d/*.conf) на станици која ради, поново учитајте конфигурацију без прекидања активне сесије:

sudo systemctl reload svxlink.service

Ово шаље SIGHUP, на који SvxLink поново учитава своју конфигурацију. Уместо тога користите sudo systemctl restart svxlink.service ако се чини да поновно учитавање не примењује неку измену (нека подешавања, на пример која се логичка језгра или звучни уређаји учитавају, могу захтевати потпуно поновно покретање).

Инсталирање старије верзије

Недавне верзије остају доступне у pool-у још неко време након што их замене новије (дневне недељу дана, недељне месец дана, месечне годину дана — погледајте одељак „Retention“ (задржавање) у UPSTREAM-SYNC.MD), тако да се лоша дневна верзија обично може вратити. Пакети upstream издања (компонента release) се никада не уклањају:

apt list -a svxlink   # или qtel; приказује све верзије које су још у репозиторијуму
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~trixie
sudo apt-mark hold svxlink   # опционо: спречава да је "apt upgrade" поново ажурира
# sudo apt-mark unhold svxlink   # касније, за наставак аутоматских ажурирања

Пакети

ПакетСадржај
svxlinkСерверске компоненте (svxlink, remotetrx, svxreflector, логичка језгра, Tcl скрипте догађаја). Изграђен са: подршком за RTL-SDR преко директне USB везе (приложени RTL-SDR Blog форк librtlsdr/rtl_tcp за актуелне V3/V4 донгле; у сукобу са пакетима дистрибуције librtlsdr0/rtl-sdr), логичким језгром SipLogic које је допринела заједница (приложени PJSIP/pjproject, статички повезан), GPIO преко libgpiod и подршком за аудио кодеке и прикључке Speex/Opus/LADSPA. Инсталира systemd сервис. Не садржи Qtel ни звучне пакете.
qtelГрафички EchoLink клијент (Qt6). Захтева графичко радно окружење и пакет svxlink потпуно исте верзије (дели његове библиотеке echolib/async).

32-битни системи: пакети armhf се граде за Raspbian (ARMv6+VFP), основу 32-битног Raspberry Pi OS-а, тако да раде на сваком моделу Raspberry Pi, укључујући Pi 1, Zero и Zero W, а инсталирају се и на Debian armhf (оба су тестирана). i386 (32-битни PC рачунари) се гради само за Debian 12: Debian 13 више не подржава инсталирање i386 система. 32-битни пакети садрже исте функције као и 64-битни.

Repozitorij APT SvxLink DB9CR

⚠ To stran je samodejno prevedla umetna inteligenca in lahko vsebuje napake. Merodajna je angleška različica. (English)

Paketi svxlink-db9cr za Raspberry Pi OS in Debian, v dveh komponentah — izberi eno:

  • main: dnevne razvojne gradnje iz najnovejše izvorne kode tega forka, ne stabilne izdaje.
  • release: uradne izdaje SvxLink izvornega projekta (26.05 in novejše), zgrajene iz nespremenjene izvorne kode izdaje z enakimi nastavitvami gradnje in funkcijami kot dnevni paketi. Vsaka izdaja se ohrani; apt upgrade preide na vsako novo izdajo izvornega projekta.

Podrobnosti najdeš v repozitoriju izvorne kode.

Izvorni projekt in lokalne spremembe

To je dnevno sinhroniziran fork projekta sm0svx/svxlink, izvirnega projekta SvxLink, z lastnim pakiranjem in dodatnimi funkcijami na vrhu (RTL-SDR, SipLogic, ločen paket qtel, ta repozitorij APT in drugo — celoten seznam je v CHANGELOG.MD). Če želiš kadar koli natančno videti, v čem se fork razlikuje od izvornega projekta, ne da bi se zanašal na zastarel posnetek na tem mestu, primerjaj v živo na GitHubu: master izvornega projekta … master tega forka.

Hiter začetek

Zaženi na ciljnem sistemu (pravilno kodno ime in arhitektura se zaznata samodejno):

# Uvoz javnega podpisnega ključa
# (sprejme se samo ključ s tem prstnim odtisom: E9CF E946 7D00 3148 AB93  EBAC 4ED4 4F53 51D8 1844)
tmp=$(mktemp -d)
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | gpg --quiet --homedir "$tmp" --import
gpg --homedir "$tmp" --export E9CFE9467D003148AB93EBAC4ED44F5351D81844 | \
  sudo tee /usr/share/keyrings/svxlink-db9cr.gpg >/dev/null
rm -rf "$tmp"

# Dodajanje vira repozitorija. Izberi komponento:
#   main     dnevne razvojne gradnje
#   release  uradne izdaje izvornega projekta (26.05 in novejše)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Obvezno pred prvim zagonom: nastavi postajo, radio in zvok.
# Datoteka iz paketa je le predloga in jo moraš prilagoditi svoji postavitvi.
sudo editor /etc/svxlink/svxlink.conf

# Omogoči SvxLink ob zagonu sistema in ga zaženi zdaj.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Preveri stanje storitve in spremljaj njen dnevnik.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Neobvezni grafični odjemalec EchoLink (potrebuje namizno okolje):
# sudo apt install qtel

Obvezno: Storitve ne zaženi, preden ne urediš datoteke /etc/svxlink/svxlink.conf. Nastavi vsaj identifikacijo postaje, logiko, sprejemnik/oddajnik ter nastavitve zvoka/PTT za svojo strojno opremo. Storitev to pot prebere prek /etc/default/svxlink.

Če apt update za ta vir javi napako 404, za kodno ime tvojega sistema paketi še niso zgrajeni (glej tabelo spodaj) — kodno ime v /etc/apt/sources.list.d/svxlink-db9cr.list zamenjaj z enim od podprtih. Nato običajni sudo apt upgrade samodejno prevzame nove dnevne gradnje (main) ali nove izdaje izvornega projekta (release).

Ne omogoči obeh komponent hkrati, razen če želiš dnevne gradnje: te imajo vedno višjo različico, zato bi jih apt namestil namesto izdaj. Če želiš obstoječo namestitev preklopiti z main na release, spremeni komponento v /etc/apt/sources.list.d/svxlink-db9cr.list, zaženi sudo apt update in nato izrecno namesti različico izdaje (gre za prehod na nižjo različico), npr. sudo apt install svxlink=26.05.2-2~deb13. Upoštevaj, da v paketih release (nespremenjena izvorna koda izvornega projekta) skripti TCL v /usr/share/svxlink niso zaščiteni kot konfiguracijske datoteke; lokalne spremembe hrani v events.d/local/.

Uveljavitev sprememb konfiguracije

Po urejanju /etc/svxlink/svxlink.conf (ali katere koli datoteke modula /etc/svxlink/svxlink.d/*.conf) na delujoči postaji konfiguracijo znova naloži, ne da bi prekinil aktivno sejo:

sudo systemctl reload svxlink.service

S tem se pošlje signal SIGHUP, ob katerem SvxLink znova prebere svojo konfiguracijo. Če se zdi, da ponovno nalaganje spremembe ni upoštevalo, namesto tega uporabi sudo systemctl restart svxlink.service (nekatere nastavitve, na primer katera logična jedra ali zvočne naprave se naložijo, morda zahtevajo popoln ponovni zagon).

Namestitev starejše različice

Nedavne različice ostanejo v poolu na voljo še nekaj časa, potem ko jih nadomestijo novejše (dnevne en teden, tedenske en mesec, mesečne eno leto — glej razdelek »Retention« (hramba) v UPSTREAM-SYNC.MD), zato je slabo dnevno gradnjo običajno mogoče povrniti. Paketi izdaj izvornega projekta (komponenta release) se nikoli ne odstranijo:

apt list -a svxlink   # ali qtel; izpiše vse različice, ki so še v repozitoriju
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~deb13
sudo apt-mark hold svxlink   # neobvezno: prepreči, da bi jo "apt upgrade" znova posodobil
# sudo apt-mark unhold svxlink   # pozneje, za nadaljevanje samodejnih posodobitev

Paketi

PaketVsebuje
svxlinkStrežniške komponente (svxlink, remotetrx, svxreflector, logična jedra, skripti dogodkov Tcl). Zgrajeno s: podporo za RTL-SDR neposredno prek USB (priložen fork librtlsdr/rtl_tcp RTL-SDR Blog za trenutne sprejemnike V3/V4; v sporu z distribucijskima paketoma librtlsdr0/rtl-sdr), prispevanim logičnim jedrom SipLogic (priložen PJSIP/pjproject, statično povezan), GPIO prek libgpiod ter podporo za zvočne kodeke in vtičnike Speex/Opus/LADSPA. Namesti storitev systemd. Ne vsebuje Qtel in zvočnih paketov. Vsebuje pravilo udev, ki storitvi SvxLink in prijavljenim uporabnikom namizja omogoča dostop do ključkov USB RTL-SDR.
qtelGrafični odjemalec EchoLink (Qt6). Potrebuje namizno okolje in paket svxlink natanko iste različice (deli njegovi knjižnici echolib/async).

32-bitni sistemi: paketi armhf so zgrajeni za Raspbian (ARMv6+VFP), osnovo 32-bitnega Raspberry Pi OS, zato delujejo na vseh modelih Raspberry Pi, vključno s Pi 1, Zero in Zero W, in jih je mogoče namestiti tudi na Debian armhf (oboje je preizkušeno). i386 (32-bitni osebni računalniki) je zgrajen samo za Debian 12: Debian 13 ne podpira več namestitve sistemov i386. 32-bitni paketi vsebujejo enake funkcije kot 64-bitni.

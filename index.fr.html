Dépôt APT SvxLink DB9CR

⚠ Cette page a été traduite automatiquement par intelligence artificielle et peut contenir des erreurs. La version anglaise fait foi. (English)

Paquets de svxlink-db9cr pour Raspberry Pi OS et Debian, répartis en deux composants — choisis-en un :

  • main : compilations de développement quotidiennes à partir des dernières sources de ce fork, et non des versions stables.
  • release : les versions officielles de SvxLink en amont (26.05 et ultérieures), compilées à partir des sources amont non modifiées, avec les mêmes paramètres de compilation et les mêmes fonctionnalités que les paquets quotidiens. Chaque version est conservée ; apt upgrade passe à chaque nouvelle version amont.

Voir le dépôt source pour plus de détails.

Amont et modifications locales

Il s'agit d'un fork, synchronisé quotidiennement, de sm0svx/svxlink, le projet SvxLink original, auquel s'ajoutent un empaquetage local et des fonctionnalités supplémentaires (RTL-SDR, SipLogic, le paquet séparé qtel, ce dépôt APT, et plus encore — voir CHANGELOG.MD pour la liste complète). Pour voir exactement ce qui diffère de l'amont à tout moment, sans dépendre d'un instantané qui deviendrait obsolète ici, compare en direct sur GitHub : master amont … master de ce fork.

Démarrage rapide

À exécuter sur le système cible (détecte automatiquement le bon nom de code et la bonne architecture) :

# Importer la clé publique de signature
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/svxlink-db9cr.gpg

# Ajouter la source du dépôt. Choisis le composant :
#   main     compilations de développement quotidiennes
#   release  versions officielles amont (26.05 et ultérieures)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Obligatoire avant le premier démarrage : configure ta station, ta radio et l'audio.
# Le fichier fourni n'est qu'un modèle et doit être adapté à ton installation.
sudo editor /etc/svxlink/svxlink.conf

# Activer SvxLink au démarrage du système et le lancer maintenant.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Vérifier l'état du service et suivre son journal.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Client EchoLink graphique optionnel (nécessite un environnement de bureau) :
# sudo apt install qtel

Obligatoire : ne démarre pas le service avant d'avoir modifié /etc/svxlink/svxlink.conf. Configure au minimum l'identité de la station, la logique, le récepteur/émetteur et les paramètres audio/PTT de ton matériel. Le service lit ce chemin via /etc/default/svxlink.

Si apt update signale une erreur 404 pour cette source, le nom de code de ton système n'est pas encore compilé (voir le tableau ci-dessous) — remplace alors le nom de code dans /etc/apt/sources.list.d/svxlink-db9cr.list par l'un de ceux qui sont pris en charge. Ensuite, un sudo apt upgrade régulier récupère automatiquement les nouvelles compilations quotidiennes (main) ou les nouvelles versions amont (release).

N'active pas les deux composants à la fois, sauf si tu veux les compilations quotidiennes : elles ont toujours la version la plus élevée, donc apt les installerait à la place des versions officielles. Pour faire passer une installation existante de main à release, change le composant dans /etc/apt/sources.list.d/svxlink-db9cr.list, exécute sudo apt update, puis installe explicitement la version release (il s'agit d'une rétrogradation), par exemple sudo apt install svxlink=26.05.2-1~trixie. Note que dans les paquets release (sources amont non modifiées), les scripts TCL sous /usr/share/svxlink ne sont pas protégés en tant que fichiers de configuration ; conserve tes modifications locales dans events.d/local/.

Appliquer des modifications de configuration

Après avoir modifié /etc/svxlink/svxlink.conf (ou tout fichier de module /etc/svxlink/svxlink.d/*.conf) sur une station en fonctionnement, recharge la configuration sans interrompre une session active :

sudo systemctl reload svxlink.service

Cela envoie SIGHUP, à la réception duquel SvxLink relit sa configuration. Utilise plutôt sudo systemctl restart svxlink.service si un rechargement ne semble pas prendre en compte une modification (certains paramètres, comme les cœurs logiques ou les périphériques audio chargés, peuvent nécessiter un redémarrage complet).

Installer une version antérieure

Les versions récentes restent disponibles dans le pool pendant un certain temps après avoir été remplacées (une par jour pendant une semaine, une par semaine pendant un mois, une par mois pendant un an — voir « Retention » (conservation) dans UPSTREAM-SYNC.MD), de sorte qu'une compilation quotidienne défectueuse peut généralement être annulée. Les paquets des versions amont (composant release) ne sont jamais supprimés :

apt list -a svxlink   # ou qtel ; liste toutes les versions encore présentes dans le dépôt
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~trixie
sudo apt-mark hold svxlink   # facultatif : empêche "apt upgrade" de la remettre à jour
# sudo apt-mark unhold svxlink   # plus tard, pour réactiver les mises à jour automatiques

Systèmes 32 bits : les paquets armhf sont compilés pour Raspbian (ARMv6+VFP), la base de Raspberry Pi OS 32 bits ; ils fonctionnent donc sur tous les modèles de Raspberry Pi, y compris le Pi 1, le Zero et le Zero W, et s'installent aussi sur Debian armhf (les deux sont testés). i386 (PC 32 bits) n'est compilé que pour Debian 12 : Debian 13 ne prend plus en charge l'installation de systèmes i386. Les paquets 32 bits offrent les mêmes fonctionnalités que les paquets 64 bits.

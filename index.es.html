Repositorio APT de SvxLink DB9CR

⚠ Esta página ha sido traducida automáticamente mediante inteligencia artificial y puede contener errores. La versión en inglés es la de referencia. (English)

Paquetes de svxlink-db9cr para Raspberry Pi OS y Debian, en dos componentes — elige uno:

  • main: compilaciones de desarrollo diarias a partir del código fuente más reciente de este fork, no versiones estables.
  • release: las versiones oficiales de SvxLink del proyecto original (26.05 y posteriores), compiladas a partir del código fuente original sin modificar, con la misma configuración de compilación y las mismas funciones que los paquetes diarios. Se conservan todas las versiones; apt upgrade pasa a cada nueva versión del proyecto original.

Consulta el repositorio de código fuente para más detalles.

Proyecto original y cambios locales

Este es un fork, sincronizado a diario, de sm0svx/svxlink, el proyecto SvxLink original, con empaquetado local y funciones adicionales añadidas encima (RTL-SDR, SipLogic, el paquete independiente qtel, este repositorio APT y más — consulta CHANGELOG.MD para la lista completa). Para ver exactamente qué difiere del proyecto original en cualquier momento, sin depender de una instantánea que aquí quedaría desactualizada, compara en directo en GitHub: master original … master de este fork.

Inicio rápido

Ejecuta en el sistema de destino (detecta automáticamente el nombre en clave y la arquitectura correctos):

# Importar la clave pública de firma
# (solo se acepta la clave con esta huella: E9CF E946 7D00 3148 AB93  EBAC 4ED4 4F53 51D8 1844)
tmp=$(mktemp -d)
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | gpg --quiet --homedir "$tmp" --import
gpg --homedir "$tmp" --export E9CFE9467D003148AB93EBAC4ED44F5351D81844 | \
  sudo tee /usr/share/keyrings/svxlink-db9cr.gpg >/dev/null
rm -rf "$tmp"

# Añadir la fuente del repositorio. Elige el componente:
#   main     compilaciones de desarrollo diarias
#   release  versiones oficiales del proyecto original (26.05 y posteriores)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Obligatorio antes del primer arranque: configura tu estación, radio y audio.
# El archivo incluido es solo una plantilla y debe adaptarse a tu instalación.
sudo editor /etc/svxlink/svxlink.conf

# Habilitar SvxLink en el arranque e iniciarlo ahora.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Comprobar el estado del servicio y seguir su registro.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Cliente gráfico de EchoLink opcional (requiere un entorno de escritorio):
# sudo apt install qtel

Obligatorio: no inicies el servicio antes de editar /etc/svxlink/svxlink.conf. Configura al menos la identidad de la estación, la lógica, el receptor/transmisor y los ajustes de audio/PTT para tu hardware. El servicio lee esta ruta a través de /etc/default/svxlink.

Si apt update devuelve un error 404 para esta fuente, el nombre en clave de tu sistema aún no se compila (ve la tabla de abajo) — en ese caso, cambia el nombre en clave en /etc/apt/sources.list.d/svxlink-db9cr.list por uno de los admitidos. Después, un sudo apt upgrade normal obtiene automáticamente las nuevas compilaciones diarias (main) o las nuevas versiones del proyecto original (release).

No habilites ambos componentes a la vez, a menos que quieras las compilaciones diarias: siempre tienen la versión más alta, por lo que apt las instalaría en lugar de las versiones oficiales. Para cambiar una instalación existente de main a release, cambia el componente en /etc/apt/sources.list.d/svxlink-db9cr.list, ejecuta sudo apt update y, a continuación, instala explícitamente la versión release (se trata de un downgrade, es decir, de una versión inferior), por ejemplo sudo apt install svxlink=26.05.2-1~trixie. Ten en cuenta que en los paquetes release (código fuente original sin modificar) los scripts TCL en /usr/share/svxlink no están protegidos como archivos de configuración; guarda los cambios locales en events.d/local/.

Aplicar cambios de configuración

Después de editar /etc/svxlink/svxlink.conf (o cualquier archivo de módulo /etc/svxlink/svxlink.d/*.conf) en una estación en funcionamiento, recárgalo sin interrumpir una sesión activa:

sudo systemctl reload svxlink.service

Esto envía la señal SIGHUP, ante la cual SvxLink vuelve a leer su configuración. Usa en su lugar sudo systemctl restart svxlink.service si una recarga no parece aplicar un cambio (algunos ajustes, como qué núcleos lógicos o dispositivos de sonido se cargan, pueden requerir un reinicio completo).

Instalar una versión anterior

Las versiones recientes siguen disponibles en el pool durante un tiempo después de ser reemplazadas (una por día durante una semana, una por semana durante un mes, una por mes durante un año — consulta «Retention» (retención) en UPSTREAM-SYNC.MD), por lo que normalmente se puede volver atrás tras una compilación diaria defectuosa. Los paquetes de versiones del proyecto original (componente release) nunca se eliminan:

apt list -a svxlink   # o qtel; muestra todas las versiones que siguen en el repositorio
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~trixie
sudo apt-mark hold svxlink   # opcional: evita que "apt upgrade" vuelva a actualizarla
# sudo apt-mark unhold svxlink   # más adelante, para reanudar las actualizaciones automáticas

PaqueteContenido
svxlinkComponentes de servidor (svxlink, remotetrx, svxreflector, núcleos lógicos, scripts de eventos Tcl). Compilado con: soporte RTL-SDR por USB directo (fork de librtlsdr/rtl_tcp de RTL-SDR Blog incluido, para los dongles V3/V4 actuales; entra en conflicto con librtlsdr0/rtl-sdr de la distribución), el núcleo lógico SipLogic aportado por la comunidad (PJSIP/pjproject incluido, enlazado estáticamente), GPIO mediante libgpiod, y soporte de códecs de audio y plugins Speex/Opus/LADSPA. qtelCliente gráfico de EchoLink (Qt6). Requiere un entorno de escritorio y el paquete svxlink exactamente de la misma versión (comparte sus bibliotecas echolib/async).

Sistemas de 32 bits: los paquetes armhf se compilan para Raspbian (ARMv6+VFP), la base de Raspberry Pi OS de 32 bits, por lo que funcionan en todos los modelos de Raspberry Pi, incluidos el Pi 1, el Zero y el Zero W, y también se instalan en Debian armhf (ambos están probados). i386 (PC de 32 bits) solo se compila para Debian 12: Debian 13 ya no admite la instalación de sistemas i386. Los paquetes de 32 bits incluyen las mismas funciones que los de 64 bits.

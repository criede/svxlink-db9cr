APT-репозиторий SvxLink DB9CR

⚠ Эта страница переведена автоматически с помощью искусственного интеллекта и может содержать ошибки. Определяющей является английская версия. (English)

Пакеты svxlink-db9cr для Raspberry Pi OS и Debian в двух компонентах — выбери один:

  • main: ежедневные сборки для разработки из самого свежего исходного кода этого форка, а не стабильные релизы.
  • release: официальные релизы SvxLink из upstream (26.05 и новее), собранные из неизменённого исходного кода upstream-релиза с теми же параметрами сборки и функциями, что и ежедневные пакеты. Каждый релиз сохраняется; apt upgrade переходит на каждый новый релиз upstream.

Подробности см. в репозитории исходного кода.

Upstream и локальные изменения

Это ежедневно синхронизируемый форк sm0svx/svxlink, оригинального проекта SvxLink, с локальной упаковкой и дополнительными функциями поверх него (RTL-SDR, SipLogic, отдельный пакет qtel, этот APT-репозиторий и другое — полный список см. в CHANGELOG.MD). Чтобы в любой момент точно увидеть, чем форк отличается от upstream, не полагаясь на снимок, который здесь может устареть, сравни актуальное состояние на GitHub: upstream master … master этого форка.

Быстрый старт

Выполни на целевой системе (нужные кодовое имя и архитектура определяются автоматически):

# Импорт открытого ключа подписи
# (принимается только ключ с этим отпечатком: E9CF E946 7D00 3148 AB93  EBAC 4ED4 4F53 51D8 1844)
tmp=$(mktemp -d)
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | gpg --quiet --homedir "$tmp" --import
gpg --homedir "$tmp" --export E9CFE9467D003148AB93EBAC4ED44F5351D81844 | \
  sudo tee /usr/share/keyrings/svxlink-db9cr.gpg >/dev/null
rm -rf "$tmp"

# Добавление источника репозитория. Выбери компонент:
#   main     ежедневные сборки для разработки
#   release  официальные релизы upstream (26.05 и новее)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Обязательно перед первым запуском: настрой станцию, радиостанцию и аудио.
# Файл из пакета является лишь шаблоном и должен быть адаптирован к твоей конфигурации.
sudo editor /etc/svxlink/svxlink.conf

# Включить автозапуск SvxLink при загрузке и запустить его сейчас.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Проверить состояние службы и следить за её журналом.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Необязательный графический клиент EchoLink (требуется окружение рабочего стола):
# sudo apt install qtel

Обязательно: Не запускай службу до редактирования /etc/svxlink/svxlink.conf. Настрой как минимум идентификацию станции, логику, приёмник/передатчик и параметры аудио/PTT для твоего оборудования. Служба получает этот путь через /etc/default/svxlink.

Если apt update сообщает об ошибке 404 для этого источника, для кодового имени твоей системы ещё нет сборок (см. таблицу ниже) — вместо этого измени кодовое имя в /etc/apt/sources.list.d/svxlink-db9cr.list на одно из поддерживаемых. После этого обычная команда sudo apt upgrade автоматически получает новые ежедневные сборки (main) или новые релизы upstream (release).

Не включай оба компонента одновременно, если только тебе не нужны ежедневные сборки: у них всегда более высокая версия, поэтому apt установил бы их вместо релизов. Чтобы перевести существующую установку с main на release, измени компонент в /etc/apt/sources.list.d/svxlink-db9cr.list, выполни sudo apt update, а затем явно установи версию релиза (это понижение версии), например sudo apt install svxlink=26.05.2-2~deb13. Обрати внимание, что в пакетах release (неизменённый исходный код upstream) скрипты TCL в /usr/share/svxlink не защищены как конфигурационные файлы; храни локальные изменения в events.d/local/.

Применение изменений конфигурации

После редактирования /etc/svxlink/svxlink.conf (или любого файла модуля /etc/svxlink/svxlink.d/*.conf) на работающей станции перезагрузи конфигурацию без разрыва активного сеанса:

sudo systemctl reload svxlink.service

Эта команда отправляет SIGHUP, по которому SvxLink повторно считывает свою конфигурацию. Используй вместо этого sudo systemctl restart svxlink.service, если перезагрузка, по-видимому, не применяет изменение (некоторые параметры, например, какие ядра логики или звуковые устройства загружаются, могут требовать полного перезапуска).

Установка более старой версии

Недавние версии остаются доступными в пуле (pool) ещё некоторое время после замены более новыми (ежедневные в течение недели, еженедельные в течение месяца, ежемесячные в течение года — см. раздел «Retention» (хранение) в UPSTREAM-SYNC.MD), поэтому неудачную ежедневную сборку обычно можно откатить. Пакеты релизов upstream (компонент release) никогда не удаляются:

apt list -a svxlink   # или qtel; показывает все версии, которые ещё есть в репозитории
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~deb13
sudo apt-mark hold svxlink   # необязательно: не даёт "apt upgrade" снова её обновить
# sudo apt-mark unhold svxlink   # позже, чтобы возобновить автоматические обновления

Пакеты

svxlinkСерверные компоненты (svxlink, remotetrx, svxreflector, ядра логики, скрипты событий Tcl). Собран с: поддержкой RTL-SDR через прямое USB-подключение (встроенный форк librtlsdr/rtl_tcp от RTL-SDR Blog для современных донглов V3/V4; конфликтует с пакетами дистрибутива librtlsdr0/rtl-sdr), предоставленным сообществом ядром логики SipLogic (встроенный PJSIP/pjproject, статически скомпонован), GPIO через libgpiod и поддержкой аудиокодеков и плагинов Speex/Opus/LADSPA. Устанавливает службу systemd. Не содержит Qtel и звуковые пакеты. Содержит правило udev, которое даёт службе SvxLink и пользователям, вошедшим в рабочий стол, доступ к USB-донглам RTL-SDR.

Поддерживаемые системы

Кодовое имяСоответствуетАрхитектуры: main (ежедневные)Архитектуры: release
bookwormDebian 12, Raspberry Pi OS Bookworm (64/32 bit)amd64 arm64 armhf i386—
trixieDebian 13, Raspberry Pi OS Trixie (64/32 bit)amd64 arm64 armhf—

32-битные системы: пакеты armhf собираются для Raspbian (ARMv6+VFP), основы 32-битной Raspberry Pi OS, поэтому они работают на всех моделях Raspberry Pi, включая Pi 1, Zero и Zero W, а также устанавливаются на Debian armhf (оба варианта протестированы). i386 (32-битные ПК) собирается только для Debian 12: Debian 13 больше не поддерживает установку систем i386. 32-битные пакеты содержат те же функции, что и 64-битные.

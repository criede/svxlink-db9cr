SvxLink DB9CR APT-hoidla

⚠ See lehekülg on tõlgitud automaatselt tehisintellekti abil ja võib sisaldada vigu. Määrav on ingliskeelne versioon. (English)

Projekti svxlink-db9cr paketid Raspberry Pi OS-i ja Debiani jaoks kahes komponendis — valige üks:

  • main: igapäevased arendusversioonid selle forgi uusimast lähtekoodist, mitte stabiilsed väljalasked.
  • release: ametlikud upstream SvxLinki väljalasked (26.05 ja uuemad), kompileeritud muutmata upstream-väljalaske lähtekoodist samade kompileerimisseadete ja funktsioonidega nagu igapäevased paketid. Kõik väljalasked säilitatakse; apt upgrade liigub igale uuele upstream-väljalaskele.

Üksikasjad leiate lähtekoodihoidlast.

Upstream ja kohalikud muudatused

See on igapäevaselt sünkroniseeritav fork projektist sm0svx/svxlink, mis on algne SvxLinki projekt, millele on lisatud kohalik pakendamine ja lisafunktsioonid (RTL-SDR, SipLogic, eraldi qtel-pakett, see APT-hoidla ja muud — täielik loetelu on failis CHANGELOG.MD). Et näha täpselt, mis on upstreamist mis tahes ajahetkel erinev, ilma et peaksite tuginema siin olevale aeguvale hetktõmmisele, võrrelge otse GitHubis: upstreami master … selle forgi master.

Kiirjuhend

Käivitage sihtsüsteemis (tuvastab õige koodnime/arhitektuuri automaatselt):

# Importige avalik allkirjastamisvõti
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/svxlink-db9cr.gpg

# Lisage hoidla allikas. Valige komponent:
#   main     igapäevased arendusversioonid
#   release  ametlikud upstream-väljalasked (26.05 ja uuemad)
component=main
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Kohustuslik enne esimest käivitamist: seadistage oma jaam, raadio ja heli.
# Paketiga kaasas olev fail on ainult mall ja see tuleb kohandada teie seadistusele.
sudo editor /etc/svxlink/svxlink.conf

# Lubage SvxLinki käivitumine alglaadimisel ja käivitage see kohe.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Kontrollige teenuse olekut ja jälgige selle logi.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Valikuline graafiline EchoLinki klient (vajab töölauakeskkonda):
# sudo apt install qtel

Nõutav: Ärge käivitage teenust enne faili /etc/svxlink/svxlink.conf muutmist. Seadistage vähemalt jaama identiteet, loogika, vastuvõtja/saatja ning heli/PTT seaded vastavalt oma riistvarale. Teenus loeb seda asukohta faili /etc/default/svxlink kaudu.

Kui apt update teatab selle allika kohta veast 404, siis teie süsteemi koodnime jaoks veel pakette ei kompileerita (vt allolevat tabelit) — muutke failis /etc/apt/sources.list.d/svxlink-db9cr.list koodnimi mõneks toetatud koodnimeks. Seejärel võtab tavaline sudo apt upgrade automaatselt kasutusele uued igapäevased versioonid (main) või uued upstream-väljalasked (release).

Ärge lubage mõlemat komponenti korraga, kui te just ei soovi igapäevaseid versioone: neil on alati kõrgem versiooninumber, seega paigaldaks apt need väljalasete asemele. Olemasoleva paigalduse vahetamiseks komponendilt main komponendile release muutke komponenti failis /etc/apt/sources.list.d/svxlink-db9cr.list, käivitage sudo apt update ja seejärel paigaldage väljalaskeversioon selgesõnaliselt (tegemist on versiooni alandamisega), nt sudo apt install svxlink=26.05.2-1~trixie. Pange tähele, et release-pakettides (muutmata upstream-lähtekood) ei ole kataloogis /usr/share/svxlink olevad TCL-skriptid konfiguratsioonifailidena kaitstud; hoidke kohalikke muudatusi kataloogis events.d/local/.

Konfiguratsioonimuudatuste rakendamine

Pärast faili /etc/svxlink/svxlink.conf (või mis tahes /etc/svxlink/svxlink.d/*.conf moodulifaili) muutmist töötavas jaamas laadige see uuesti ilma aktiivset seanssi katkestamata:

sudo systemctl reload svxlink.service

See saadab signaali SIGHUP, mille peale SvxLink loeb oma konfiguratsiooni uuesti. Kasutage selle asemel käsku sudo systemctl restart svxlink.service, kui uuesti laadimine ei näi muudatust rakendavat (mõned seaded, näiteks milliseid loogikatuumasid või heliseadmeid laaditakse, võivad vajada täielikku taaskäivitamist).

Vanema versiooni paigaldamine

Hiljutised versioonid jäävad pärast uuemaga asendamist mõneks ajaks pooli kättesaadavaks (igapäevased nädalaks, iganädalased kuuks, igakuised aastaks — vt jaotist "Retention" (säilitamine) failis UPSTREAM-SYNC.MD), nii et halva igapäevase versiooni saab tavaliselt tagasi pöörata. Upstream-väljalaskepakette (release-komponent) ei eemaldata kunagi:

apt list -a svxlink   # või qtel; loetleb kõik hoidlas veel olevad versioonid
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~trixie
sudo apt-mark hold svxlink   # valikuline: takistab, et "apt upgrade" seda uuesti uuendaks
# sudo apt-mark unhold svxlink   # hiljem, automaatsete uuenduste jätkamiseks

Paketid

PakettSisu
svxlinkServerikomponendid (svxlink, remotetrx, svxreflector, loogikatuumad, Tcl-sündmusskriptid). Kompileeritud järgmisega: RTL-SDR otse-USB tugi (kaasas RTL-SDR Blogi librtlsdr/rtl_tcp fork praeguste V3/V4 donglite jaoks; on vastuolus distributsiooni pakettidega librtlsdr0/rtl-sdr), kogukonna panustatud SipLogic loogikatuum (kaasas PJSIP/pjproject, staatiliselt lingitud), GPIO libgpiodi kaudu ning Speex/Opus/LADSPA helikoodekite ja pistikprogrammide tugi. Paigaldab systemd-teenuse. Ei sisalda Qteli ega helipakette.
qtelGraafiline EchoLinki klient (Qt6). Vajab töölauakeskkonda ja täpselt sama versiooniga svxlink-paketti (kasutab selle echolib/async teeke).

Toetatud süsteemid

KoodnimiVastabArhitektuurid: main (igapäevane)Arhitektuurid: release
bookwormDebian 12, Raspberry Pi OS Bookworm (64/32 bit)amd64 arm64 armhf i386—
trixieDebian 13, Raspberry Pi OS Trixie (64/32 bit)amd64 arm64 armhf—

32-bitised süsteemid: armhf-paketid kompileeritakse Raspbiani (ARMv6+VFP) vastu, mis on 32-bitise Raspberry Pi OS-i alus, seega töötavad need kõigil Raspberry Pi mudelitel, sealhulgas Pi 1, Zero ja Zero W, ning neid saab paigaldada ka Debiani armhf-süsteemile (mõlemat on testitud). i386 (32-bitised arvutid) kompileeritakse ainult Debian 12 jaoks: Debian 13 ei toeta enam i386-süsteemide paigaldamist. 32-bitistel pakettidel on samad funktsioonid kui 64-bitistel.

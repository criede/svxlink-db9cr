APT-репозиторій SvxLink DB9CR

⚠ Цю сторінку перекладено автоматично за допомогою штучного інтелекту, тому вона може містити помилки. Чинною є англійська версія. (English)

Пакети svxlink-db9cr для Raspberry Pi OS і Debian у двох компонентах — обери один:

  • main: щоденні збірки для розробки з найновішого вихідного коду цього форку, а не стабільні випуски.
  • release: офіційні випуски SvxLink з upstream (26.05 і новіші), зібрані з незміненого вихідного коду upstream-випуску з тими самими параметрами збирання та функціями, що й щоденні пакети. Кожен випуск зберігається; apt upgrade переходить на кожен новий випуск upstream.

Подробиці див. у репозиторії вихідного коду.

Upstream і локальні зміни

Це щоденно синхронізований форк sm0svx/svxlink, оригінального проєкту SvxLink, з локальним пакуванням і додатковими функціями поверх нього (RTL-SDR, SipLogic, окремий пакет qtel, цей APT-репозиторій та інше — повний перелік див. у CHANGELOG.MD). Щоб будь-коли точно побачити, чим форк відрізняється від upstream, не покладаючись на знімок тут, який може застаріти, порівняй актуальний стан на GitHub: upstream master … master цього форку.

Швидкий старт

Виконай на цільовій системі (потрібні кодова назва та архітектура визначаються автоматично):

# Імпорт відкритого ключа підпису
# (приймається лише ключ із цим відбитком: E9CF E946 7D00 3148 AB93  EBAC 4ED4 4F53 51D8 1844)
tmp=$(mktemp -d)
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | gpg --quiet --homedir "$tmp" --import
gpg --homedir "$tmp" --export E9CFE9467D003148AB93EBAC4ED44F5351D81844 | \
  sudo tee /usr/share/keyrings/svxlink-db9cr.gpg >/dev/null
rm -rf "$tmp"

# Додавання джерела репозиторію. Обери компонент:
#   main     щоденні збірки для розробки
#   release  офіційні випуски upstream (26.05 і новіші)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Обов’язково перед першим запуском: налаштуй станцію, радіостанцію та аудіо.
# Файл із пакета є лише шаблоном і має бути адаптований до твоєї конфігурації.
sudo editor /etc/svxlink/svxlink.conf

# Увімкнути запуск SvxLink під час завантаження системи та запустити його зараз.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Перевірити стан служби та стежити за її журналом.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Необов’язковий графічний клієнт EchoLink (потрібне стільничне середовище):
# sudo apt install qtel

Обов’язково: Не запускай службу до редагування /etc/svxlink/svxlink.conf. Налаштуй щонайменше ідентифікацію станції, логіку, приймач/передавач і параметри аудіо/PTT для твого обладнання. Служба отримує цей шлях через /etc/default/svxlink.

Якщо apt update повідомляє про помилку 404 для цього джерела, для кодової назви твоєї системи ще немає збірок (див. таблицю нижче) — натомість зміни кодову назву в /etc/apt/sources.list.d/svxlink-db9cr.list на одну з підтримуваних. Після цього звичайна команда sudo apt upgrade автоматично отримує нові щоденні збірки (main) або нові випуски upstream (release).

Не вмикай обидва компоненти одночасно, якщо тільки тобі не потрібні щоденні збірки: вони завжди мають вищу версію, тож apt установив би їх замість випусків. Щоб перевести наявну інсталяцію з main на release, зміни компонент у /etc/apt/sources.list.d/svxlink-db9cr.list, виконай sudo apt update, а потім явно встанови версію випуску (це пониження версії), наприклад sudo apt install svxlink=26.05.2-2~deb13. Зверни увагу, що в пакетах release (незмінений вихідний код upstream) скрипти TCL у /usr/share/svxlink не захищені як конфігураційні файли; зберігай локальні зміни в events.d/local/.

Застосування змін конфігурації

Після редагування /etc/svxlink/svxlink.conf (або будь-якого файлу модуля /etc/svxlink/svxlink.d/*.conf) на працюючій станції перезавантаж конфігурацію без розриву активного сеансу:

sudo systemctl reload svxlink.service

Ця команда надсилає SIGHUP, за яким SvxLink повторно зчитує свою конфігурацію. Натомість використовуй sudo systemctl restart svxlink.service, якщо перезавантаження, схоже, не застосовує зміну (деякі параметри, наприклад, які ядра логіки чи звукові пристрої завантажуються, можуть потребувати повного перезапуску).

Встановлення старішої версії

Нещодавні версії залишаються доступними в пулі (pool) ще деякий час після заміни новішими (щоденні протягом тижня, щотижневі протягом місяця, щомісячні протягом року — див. розділ «Retention» (зберігання) у UPSTREAM-SYNC.MD), тож невдалу щоденну збірку зазвичай можна відкотити. Пакети випусків upstream (компонент release) ніколи не видаляються:

apt list -a svxlink   # або qtel; показує всі версії, які ще є в репозиторії
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~deb13
sudo apt-mark hold svxlink   # необов’язково: не дає "apt upgrade" знову її оновити
# sudo apt-mark unhold svxlink   # пізніше, щоб відновити автоматичні оновлення

Пакети

ПакетВміст
svxlinkСерверні компоненти (svxlink, remotetrx, svxreflector, ядра логіки, скрипти подій Tcl). Зібрано з: підтримкою RTL-SDR через пряме USB-підключення (вбудований форк librtlsdr/rtl_tcp від RTL-SDR Blog для сучасних донглів V3/V4; конфліктує з пакетами дистрибутива librtlsdr0/rtl-sdr), наданим спільнотою ядром логіки SipLogic (вбудований PJSIP/pjproject, статично скомпонований), GPIO через libgpiod і підтримкою аудіокодеків і плагінів Speex/Opus/LADSPA. Встановлює службу systemd. Не містить Qtel і звукових пакетів. Містить правило udev, яке надає службі SvxLink і користувачам, що увійшли в робочий стіл, доступ до USB-донглів RTL-SDR.
qtelГрафічний клієнт EchoLink (Qt6). Потребує стільничного середовища та пакета svxlink точно тієї самої версії (використовує його бібліотеки echolib/async).

32-бітні системи: пакети armhf збираються під Raspbian (ARMv6+VFP), основу 32-бітної Raspberry Pi OS, тож вони працюють на всіх моделях Raspberry Pi, включно з Pi 1, Zero та Zero W, а також встановлюються на Debian armhf (обидва варіанти протестовано). i386 (32-бітні ПК) збирається лише для Debian 12: Debian 13 більше не підтримує встановлення систем i386. 32-бітні пакети містять ті самі функції, що й 64-бітні.

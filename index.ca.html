Repositori APT de SvxLink DB9CR

⚠ Aquesta pàgina s’ha traduït automàticament amb intel·ligència artificial i pot contenir errors. La versió anglesa és la de referència. (English)

Paquets de svxlink-db9cr per a Raspberry Pi OS i Debian, en dos components — trieu-ne un:

  • main: compilacions de desenvolupament diàries a partir del codi font més recent d'aquest fork, no versions estables.
  • release: les versions oficials de SvxLink del projecte original (26.05 i posteriors), compilades a partir del codi font original sense modificar, amb la mateixa configuració de compilació i les mateixes funcionalitats que els paquets diaris. Es conserven totes les versions; apt upgrade passa a cada nova versió del projecte original.

Consulteu el repositori de codi font per a més detalls.

Projecte original i canvis locals

Aquest és un fork, sincronitzat diàriament, de sm0svx/svxlink, el projecte SvxLink original, amb empaquetament local i funcionalitats addicionals afegides al damunt (RTL-SDR, SipLogic, el paquet separat qtel, aquest repositori APT i més — vegeu CHANGELOG.MD per a la llista completa). Per veure exactament què és diferent del projecte original en qualsevol moment, sense dependre d'una instantània d'aquí que quedi desactualitzada, compareu-ho en directe a GitHub: master original … master d'aquest fork.

Inici ràpid

Executeu-ho al sistema de destinació (detecta automàticament el nom en clau i l'arquitectura correctes):

# Importar la clau pública de signatura
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | \
  sudo gpg --dearmor -o /usr/share/keyrings/svxlink-db9cr.gpg

# Afegir la font del repositori. Trieu el component:
#   main     compilacions de desenvolupament diàries
#   release  versions oficials del projecte original (26.05 i posteriors)
component=main
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Obligatori abans del primer inici: configureu l'estació, la ràdio i l'àudio.
# El fitxer inclòs és només una plantilla i s'ha d'adaptar a la vostra instal·lació.
sudo editor /etc/svxlink/svxlink.conf

# Habilitar SvxLink en l'arrencada i iniciar-lo ara.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Comprovar l'estat del servei i seguir-ne el registre.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Client gràfic d'EchoLink opcional (necessita un entorn d'escriptori):
# sudo apt install qtel

Obligatori: no inicieu el servei abans d'editar /etc/svxlink/svxlink.conf. Configureu com a mínim la identitat de l'estació, la lògica, el receptor/transmissor i els paràmetres d'àudio/PTT per al vostre maquinari. El servei llegeix aquest camí a través de /etc/default/svxlink.

Si apt update informa d'un error 404 per a aquesta font, el nom en clau del vostre sistema encara no es compila (vegeu la taula següent) — en aquest cas, canvieu el nom en clau a /etc/apt/sources.list.d/svxlink-db9cr.list per un dels que són compatibles. Després, un sudo apt upgrade habitual obté automàticament les noves compilacions diàries (main) o les noves versions del projecte original (release).

No habiliteu tots dos components alhora, tret que vulgueu les compilacions diàries: sempre tenen la versió més alta, de manera que apt les instal·laria en lloc de les versions oficials. Per canviar una instal·lació existent de main a release, canvieu el component a /etc/apt/sources.list.d/svxlink-db9cr.list, executeu sudo apt update i després instal·leu explícitament la versió release (és un downgrade, és a dir, una versió inferior), per exemple sudo apt install svxlink=26.05.2-1~trixie. Tingueu en compte que, als paquets release (codi font original sense modificar), els scripts TCL de /usr/share/svxlink no estan protegits com a fitxers de configuració; deseu els canvis locals a events.d/local/.

Aplicar canvis de configuració

Després d'editar /etc/svxlink/svxlink.conf (o qualsevol fitxer de mòdul /etc/svxlink/svxlink.d/*.conf) en una estació en funcionament, torneu-la a carregar sense interrompre una sessió activa:

sudo systemctl reload svxlink.service

Això envia el senyal SIGHUP, en rebre el qual SvxLink torna a llegir la seva configuració. Feu servir sudo systemctl restart svxlink.service en lloc d'això si una recàrrega no sembla aplicar un canvi (alguns paràmetres, com ara quins nuclis lògics o dispositius de so es carreguen, poden requerir un reinici complet).

Instal·lar una versió anterior

Les versions recents continuen disponibles al pool durant un temps després de ser substituïdes (una per dia durant una setmana, una per setmana durant un mes, una per mes durant un any — vegeu «Retention» (retenció) a UPSTREAM-SYNC.MD), de manera que normalment es pot tornar enrere després d'una compilació diària defectuosa. Els paquets de les versions del projecte original (component release) no s'eliminen mai:

apt list -a svxlink   # o qtel; mostra totes les versions que encara són al repositori
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~trixie
sudo apt-mark hold svxlink   # opcional: evita que "apt upgrade" la torni a actualitzar
# sudo apt-mark unhold svxlink   # més endavant, per reprendre les actualitzacions automàtiques

Sistemes de 32 bits: els paquets armhf es compilen per a Raspbian (ARMv6+VFP), la base del Raspberry Pi OS de 32 bits, de manera que funcionen en tots els models de Raspberry Pi, inclosos el Pi 1, el Zero i el Zero W, i també s'instal·len a Debian armhf (tots dos estan provats). i386 (PC de 32 bits) només es compila per a Debian 12: Debian 13 ja no admet la instal·lació de sistemes i386. Els paquets de 32 bits contenen les mateixes funcionalitats que els de 64 bits.

APT repozitář SvxLink DB9CR

⚠ Tato stránka byla přeložena automaticky pomocí umělé inteligence a může obsahovat chyby. Závazná je anglická verze. (English)

Balíčky svxlink-db9cr pro Raspberry Pi OS a Debian ve dvou komponentách — vyber si jednu:

  • main: denní vývojová sestavení z nejnovějšího zdrojového kódu tohoto forku, nikoli stabilní vydání.
  • release: oficiální vydání SvxLink z mateřského projektu (26.05 a novější), sestavená z nezměněného zdrojového kódu vydání se stejným nastavením sestavení a funkcemi jako denní balíčky. Každé vydání je zachováno; apt upgrade přechází na každé nové vydání mateřského projektu.

Podrobnosti najdeš ve zdrojovém repozitáři.

Mateřský projekt a místní změny

Jde o denně synchronizovaný fork sm0svx/svxlink, původního projektu SvxLink, s vlastním balíčkováním a rozšířeními funkcí navrch (RTL-SDR, SipLogic, samostatný balíček qtel, tento APT repozitář a další — úplný seznam viz CHANGELOG.MD). Chceš-li kdykoli zjistit, čím přesně se fork liší od mateřského projektu, aniž by ses spoléhal na zastaralý snímek na této stránce, porovnej to živě na GitHubu: master mateřského projektu … master tohoto forku.

Rychlý start

Spusť na cílovém systému (správné kódové jméno a architektura se zjistí automaticky):

# Import veřejného podpisového klíče
# (přijme se jen klíč s tímto otiskem: E9CF E946 7D00 3148 AB93  EBAC 4ED4 4F53 51D8 1844)
tmp=$(mktemp -d)
curl -fsSL https://criede.github.io/svxlink-db9cr/pubkey.gpg | gpg --quiet --homedir "$tmp" --import
gpg --homedir "$tmp" --export E9CFE9467D003148AB93EBAC4ED44F5351D81844 | \
  sudo tee /usr/share/keyrings/svxlink-db9cr.gpg >/dev/null
rm -rf "$tmp"

# Přidání zdroje repozitáře. Zvol komponentu:
#   main     denní vývojová sestavení
#   release  oficiální vydání mateřského projektu (26.05 a novější)
component=release
codename=$(sed -n 's/^VERSION_CODENAME=//p' /etc/os-release | tr -d '"')
arch=$(dpkg --print-architecture)
echo "deb [signed-by=/usr/share/keyrings/svxlink-db9cr.gpg arch=${arch}] https://criede.github.io/svxlink-db9cr ${codename} ${component}" | \
  sudo tee /etc/apt/sources.list.d/svxlink-db9cr.list

sudo apt update
sudo apt install svxlink

# Povinné před prvním spuštěním: nakonfiguruj stanici, rádio a audio.
# Soubor z balíčku je pouze šablona a musí být přizpůsoben tvé sestavě.
sudo editor /etc/svxlink/svxlink.conf

# Povolení SvxLink při startu systému a jeho okamžité spuštění.
sudo systemctl daemon-reload
sudo systemctl enable --now svxlink.service

# Kontrola stavu služby a sledování jejího protokolu.
systemctl status svxlink.service
journalctl -u svxlink.service -f

# Volitelný grafický klient EchoLink (vyžaduje grafické prostředí):
# sudo apt install qtel

Povinné: Nespouštěj službu před úpravou souboru /etc/svxlink/svxlink.conf. Nastav alespoň identifikaci stanice, logiku, přijímač/vysílač a nastavení audia/PTT pro svůj hardware. Služba čte tuto cestu přes /etc/default/svxlink.

Pokud apt update hlásí pro tento zdroj chybu 404, pro kódové jméno tvého systému se zatím nesestavuje (viz tabulka níže) — změň kódové jméno v /etc/apt/sources.list.d/svxlink-db9cr.list na některé z podporovaných. Poté běžný příkaz sudo apt upgrade automaticky stáhne nová denní sestavení (main) nebo nová vydání mateřského projektu (release).

Nepovoluj obě komponenty současně, pokud nechceš denní sestavení: ta mají vždy vyšší verzi, takže by je apt nainstaloval místo vydání. Chceš-li přepnout stávající instalaci z main na release, změň komponentu v /etc/apt/sources.list.d/svxlink-db9cr.list, spusť sudo apt update a poté explicitně nainstaluj verzi vydání (jde o downgrade, tj. přechod na nižší verzi), např. sudo apt install svxlink=26.05.2-2~deb13. Upozorňujeme, že v balíčcích release (nezměněný zdrojový kód mateřského projektu) nejsou skripty TCL v /usr/share/svxlink chráněny jako konfigurační soubory; místní změny ukládej do events.d/local/.

Použití změn konfigurace

Po úpravě /etc/svxlink/svxlink.conf (nebo libovolného souboru modulu /etc/svxlink/svxlink.d/*.conf) na běžící stanici konfiguraci znovu načti bez přerušení aktivní relace:

sudo systemctl reload svxlink.service

Tím se odešle signál SIGHUP, na který SvxLink znovu načte svou konfiguraci. Pokud se zdá, že opětovné načtení změnu nepřevzalo, použij místo toho sudo systemctl restart svxlink.service (některá nastavení, například které logická jádra nebo zvuková zařízení se načítají, mohou vyžadovat úplný restart).

Instalace starší verze

Nedávné verze zůstávají po nahrazení novější verzí ještě nějakou dobu dostupné v poolu (denní po dobu týdne, týdenní po dobu měsíce, měsíční po dobu roku — viz oddíl „Retention“ (uchovávání) v UPSTREAM-SYNC.MD), takže vadné denní sestavení lze obvykle vrátit zpět. Balíčky vydání mateřského projektu (komponenta release) se nikdy neodstraňují:

apt list -a svxlink   # nebo qtel; vypíše všechny verze, které jsou v repozitáři ještě k dispozici
sudo apt install svxlink=26.05.1+daily20260910.5.1.gabcdef012345-1~deb13
sudo apt-mark hold svxlink   # volitelné: zabrání tomu, aby ji "apt upgrade" opět povýšil
# sudo apt-mark unhold svxlink   # později, pro obnovení automatických aktualizací

Balíčky

BalíčekObsah
svxlinkServerové komponenty (svxlink, remotetrx, svxreflector, logická jádra, skripty událostí Tcl). Sestaveno s: podporou RTL-SDR přímo přes USB (přibalený fork librtlsdr/rtl_tcp od RTL-SDR Blog pro aktuální přijímače V3/V4; koliduje s distribučními balíčky librtlsdr0/rtl-sdr), přispěným logickým jádrem SipLogic (přibalený PJSIP/pjproject, staticky linkovaný), GPIO přes libgpiod a podporou audio kodeků a pluginů Speex/Opus/LADSPA. Instaluje službu systemd. Neobsahuje Qtel ani zvukové balíčky. Obsahuje pravidlo udev, které službě SvxLink a přihlášeným uživatelům desktopu umožňuje přístup k USB donglům RTL-SDR.
qtelGrafický klient EchoLink (Qt6). Vyžaduje grafické prostředí a balíček svxlink v přesně stejné verzi (sdílí jeho knihovny echolib/async).

32bitové systémy: balíčky armhf se sestavují proti Raspbianu (ARMv6+VFP), základu 32bitového Raspberry Pi OS, takže běží na všech modelech Raspberry Pi včetně Pi 1, Zero a Zero W a lze je nainstalovat i na Debian armhf (obojí je testováno). i386 (32bitová PC) se sestavuje pouze pro Debian 12: Debian 13 již nepodporuje instalaci systémů i386. 32bitové balíčky obsahují stejné funkce jako 64bitové.
